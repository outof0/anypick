title: CLI reference
description: Every AnyPick command, global flag, exit code, and environment variable.
---

The command name is `anypick`. Download a checksum-listed archive from the
GitHub Release, or install the thin npm launcher with
`npm install --global anypick` (Node 18+; downloads the matching native CLI on
first run). During development, run the same command tree from a checkout with
`make run ARGS="…"`; for example, `make run ARGS="list accounts"`.

The native macOS application is a separate app-owned target. It launches its
bundled Go service itself and does not need this CLI to parent it.

## Global flags

Valid on every command.

| Flag | Effect |
| --- | --- |
| `-V, --version` | Print the version and exit |
| `--json` | Machine-readable output |
| `-v, --verbose` | Verbose logging |
| `-q, --quiet` | Minimal output |
| `--dry-run` | Print the plan; write nothing |
| `--reveal` | Show secrets — dangerous |
| `--no-input` | Never prompt, even on a TTY |
| `-y, --yes` | Skip destructive confirmations |
| `--trace` | Print internal step names, without secrets |
| `--tui` | Open the Terminal UI for this run |
| `--tray` | Select the compatibility tray surface for this source CLI run |

## Bindings

```bash
anypick use <client> --with <source> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick use codex --with <source> --profile <name> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick run <client> (--with <source>|--profile <name>) [--model <id>] -- <args…>
anypick codex profile login <name> [--auth-method <id>] [--source <id>]
anypick codex profile list
anypick codex profile show <name>
anypick codex profile remove <name> [--yes]
anypick current <provider>
anypick models <client> [--with <source>]
anypick link <client> [--with <source>] [--model <id>] [--allow-foreign-config]
anypick unlink [client]
anypick reset [client]
```

| Command | Description |
| --- | --- |
| `use` | Set what a client uses by default (`--with` is required) |
| `run` | Launch a client with its effective binding |
| `current` | Show one provider's effective bindings |
| `models` | List the model ids the bound source publishes |
| `link` / `unlink` | Project-scoped bindings for the current directory; `link` without `--with` re-applies the stored global spec |
| `reset` | Remove AnyPick-managed configuration for a client |

`--with` accepts an account (`grok/work`), a gateway name, a pool
(`pool:gemini`), the Proxy Hub (`hub:default`), or a preset (`@work-stack`).
`--transport` pins the route policy instead of letting the planner choose.

#### Client configs AnyPick does not own

AnyPick writes other tools' config files, so it refuses to replace a value it
cannot prove it wrote. If `~/.claude/settings.json` or a Codex config already
points at your own login or endpoint, `use` fails with `CLIENT_CONFIG_FOREIGN`
and names the file and the keys at stake — the config is left byte-identical.

`--allow-foreign-config` is the explicit answer: it backs the current file up
under `$ANYPICK_HOME/recovery/clients/<client>/` and then replaces those values.
Consent is per run and never persisted, and the desktop app asks the same
question with a **Manage with AnyPick** button instead of a flag. A client
AnyPick already manages (a loopback proxy endpoint, or a config carrying
AnyPick's managed marker) is updated without asking.

### Named Codex profiles

`--profile` gives Codex a stable native profile name while AnyPick stores the
source behind it. This is useful when one shell or script needs several saved
routes: each profile has its own `CODEX_HOME`, `<name>.config.toml`, and
`auth.json`. Proxy-backed profiles also get an owner-only environment file.

For a saved Codex account, `auto` uses a native profile home and copies that
account's saved `auth.json`; it does not touch the desktop app's live
`CODEX_HOME`. To create an account and profile without switching the desktop
login, use `profile login`:

```bash
anypick codex profile login work
anypick use codex --with codex/work --profile work --model gpt-5.6
anypick use codex --with openrouter-work --profile gateway
anypick use codex --with hub:default --profile hub-work
```

`profile login` runs the official Codex login with
`CODEX_HOME=$ANYPICK_HOME/clients/codex/profiles/work/codex-home`, so the
browser flow writes account B there. AnyPick then saves the same file as the
`codex/work` snapshot and restores the desktop active pointer. To use an
account-backed proxy instead, enable it and pin `--transport proxy`:

```bash
anypick proxy enable codex work
anypick use codex --with codex/work --profile work-proxy --transport proxy
```

The default Codex CLI config accepts the same routes without `--profile`:

```bash
anypick use codex --with codex/work --transport proxy
anypick use codex --with hub:default
```

To run a profile through an isolated Codex CLI process, use:

```bash
anypick run codex --profile personal -- exec --help
anypick codex profile list
```

For a raw invocation, use the `launch` command printed by
`anypick codex profile show <name>`. It sets the profile-specific `CODEX_HOME`
explicitly; proxy-backed profiles also source their owner-only env file. Do not
print or commit that env file: it contains the local proxy credential.
Hub-backed profiles have distinct route tokens, so activating one profile
does not invalidate the default route or another profile. These commands
configure Codex CLI; Codex Desktop keeps its own signed-in account and does
not follow the CLI's `CODEX_HOME`.

`anypick codex profile remove <name>` deletes the route and the files AnyPick
generated for it (the profile config, its model catalog, and its env file). The
profile's private `CODEX_HOME` stays in place, so signing in again under the
same name reuses it. Removing the *account* a profile points at is different:
`anypick account remove codex work` also removes the named profiles bound to
that account, credential home included, and names them in the result. Profiles
that point at a gateway, a Hub, a pool, or a different account are not touched.
AnyPick sweeps profiles left over from an earlier delete at the next startup,
and `anypick doctor` reports them until then.

<Aside type="caution" title="Non-interactive use">
`use <client>` requires `--with`. Without it there is nothing to derive the
source from, so the command exits `2` instead of guessing.
</Aside>

## Inventory

```bash
anypick list [providers|accounts]   # default: providers
anypick providers
anypick clients
```

There is no `ls` alias and no `list gateways|clients|presets` form: gateways,
presets, and plugins each have their own command family below.

## Adding sources

```bash
anypick add account <provider> --name <name> [--current|--new] [--source <id>] [--force]
anypick add account <provider> --new --name <name> [--auth-method <id>] [--source <id>]
anypick add account <provider> --name <name> --credential <kind> --secret [--option profile=<id>] [--region <region>]
anypick add gateway <name> --provider <id> [--endpoint url]
    [--api-key [key] | --api-key-env <var> | --secret <key>]
    [--model <id>] [--models <role=id>]
```

`--current` snapshots the login that is live now. `--new` uses an available
provider-owned browser sign-in and saves its resulting native credential;
otherwise it stashes the current login and prints the manual continuation.
Official methods are preferred, while `--auth-method <id>` can select any method
the provider declares, including a community method. `--source <id>` picks an
explicit native store for a multi-source provider. `--credential <kind>`
(covers `--api-key` for compatible providers) plus `--secret`, `--api-key`, or
a bare `--api-key` prompt supplies an API-key credential; `--profile` or
`--option profile=<id>` selects an endpoint profile, and `--region` is the
Kiro API-key cloud region. Omit the `--secret` value to use a masked prompt, or
pass it through `ANYPICK_SECRET`.

## Accounts

```bash
anypick account list [provider]
anypick account refresh [provider [name]] [--all]
anypick account remove <provider> <name> [--yes]
anypick account export <provider> <name> [--out <file>]   # -o <file>; defaults to ~/.anypick/exports/*.json
anypick account export [provider] --all [--out <file>] [--overwrite]
anypick account import <provider> <name> <file.json> [--force]   # or -i <file.json>
anypick account import <file.json> [<file2.json> …] [--force]
```

`refresh` adopts the provider's current live login into a saved account. With no
provider it tries every saved account; with a provider (and optionally a name)
it refreshes just those. A refresh that would give one account another account's
snapshot is refused — one login stays one account — so refreshing a whole
provider cannot silently collapse distinct logins into the current live one.
There is no `rm` alias.

## Gateways

```bash
anypick gateway add <name> --provider <id> [--endpoint url]
    [--api-key [key]|--api-key-env <var>|--secret <key>]
    [--model <id>] [--models <role=id>]
anypick gateway list
anypick gateway show <name>
anypick gateway edit <name> [--endpoint url] [--model id] [-m id] [--api-key key]
anypick gateway remove <name>
```

`show` masks the API key unless you pass the global `--reveal`. `edit` accepts
`--api-key` to replace the stored key, and `-m` as the short form of `--model`.

## Presets

```bash
anypick preset list
anypick preset show <name>
anypick preset remove <name>
```

Preset names are written without the `@` here; the `@` prefix is only how you
reference one in `--with`.

## Proxies

```bash
anypick proxy enable|disable <provider> <account> [--port N]
anypick proxy start|stop|status|token <provider> <account>
anypick proxy config <provider> <account> [--port N]
anypick proxy restart <provider> <account>
anypick proxy logs <provider> <account> [--lines N] [--follow]
```

`--port` on `enable`/`config` pins a port; otherwise the first free port is
used. `token` prints or rotates (`--rotate`) the authentication token / API key
for the proxy. After a rotation on a running proxy, AnyPick checks that the new
key is accepted and the previous one is refused, then updates every client
bound to that account. A client whose settings you moved off AnyPick's route
is left alone unless you add `--allow-foreign-config`. Rotating the first
member of a running pool keeps the pool running. `logs` prints the last 50
lines by default.

### Pools

```bash
anypick proxy pool status <provider>
anypick proxy pool enable <provider> [--strategy failover|round-robin|soonest-reset]
    [--mode single|multi] [--port N] [-p N] [+account|-account ...]
anypick proxy pool member <provider> <account> <on|off>
anypick proxy pool start <provider>
anypick proxy pool stop <provider>
anypick proxy pool disable <provider>
```

`enable` adds `+account` members and pauses `-account` ones in one call; the
default strategy is `failover`, the default mode `multi`. With `round-robin`
each request starts at the next eligible member; with `failover` the account
that last answered keeps serving until it is rejected. Either way a
quota-class failure moves the request on to the next member.

### Proxy Hub

```bash
anypick proxy hub status <name>
anypick proxy hub enable <name> [--host <host>] [--port N] [-p N]
    [--strategy failover|round-robin|soonest-reset] [--start]
anypick proxy hub source <name> <provider> <account>
anypick proxy hub owner <name> <model> <provider>/<account>
anypick proxy hub preview <name>
anypick proxy hub start <name>
anypick proxy hub stop <name>
anypick proxy hub combo add <name> <combo> <provider/account=model>...
anypick proxy hub combo list <name>
anypick proxy hub combo remove <name> <combo>
```

`source` toggles: present sources are removed, absent ones added (an account
name is required). `--strategy round-robin` makes the hub spread each model
across the enabled accounts that can serve it — the accounts of the provider the
model resolves to — instead of pinning it to one; without the flag the current
mode is kept. Bind with `--with hub:<name>` after at least one source is
enabled. `owner` picks which account wins when two sources advertise the same
model id; `preview` refreshes catalogs and prints routes plus conflicts.
`combo` manages named fallback chains the hub serves as model ids; see
[Combos](/docs/guides/proxies#combos-model-ids-the-hub-defines).

## Plugins

```bash
anypick plugin list
anypick plugin add <dir>
anypick plugin enable <name>
anypick plugin disable <name>
anypick plugin trust <name>
anypick plugin remove <name>
```

`add` installs a local directory **disabled**. `enable` is the trust decision and
prompts; it needs the global `-y` when there is no TTY. `trust` re-pins the
package digest after the plugin's code changes. See
[Plugins](/docs/guides/plugins).

## Source CLI surfaces and compatibility supervisor

```bash
anypick tui
anypick tray
anypick start
anypick status
anypick stop
```

`anypick tui` always opens the [Apps / Terminal UI](/docs/guides/terminal-ui).
The `tray` command family is implemented by the Go engine (the TypeScript tree
and its tray surface no longer exist): `anypick tray` prints the compatibility
snapshot, while `start`, `status`, and `stop` control the compatibility
supervisor and the proxies it owns.

These commands do not define native-app ownership. The macOS app resolves and
starts `Contents/Helpers/anypick-core`, keeps the menu-bar quick panel inside the
same application, and stops the helper on explicit app Quit. See
[macOS app and menu bar](/docs/guides/tray).

## Usage history

```bash
anypick usage [--since 7d|24h|2026-10-01] [--by model|account|provider|day] [--json]
```

Shows the tokens that running proxies, pools and Proxy Hubs served, with a
cost estimate at API list prices. `--since` defaults to `7d`; history is kept
for 90 days. `--by` defaults to `model`. What is recorded, how the estimate is
made and how to add prices are in [Usage and cost](/docs/guides/usage).

## Update checks

```bash
anypick update
anypick update --json
```

This advisory check compares the running version with the latest GitHub
release. It prints the available install route; it does not change the
installation. The guidance points to the release page, an available package
manager, or a source checkout:

```bash
git pull && make build
```

Until a release is published, the check reports `no published release yet` and
points at the source workflow. `--json` returns the current and latest versions:

```bash
anypick update --json
```

```json
{ "current": "1.0.0", "latest": "1.1.0" }
```

The update engine also has explicit check and download commands. The macOS
**Settings → Updates** pane uses the same commands:

```bash
anypick update check --json
anypick update download --json
```

`check` reports the update state and the install action for the detected
channel. `download` fetches a direct-install asset into AnyPick's user cache
and checks its SHA-256 against the checksum file from that release. It does
not replace or restart the installed app. In Settings, **Show in Finder** opens
the downloaded file so you can install it using the usual steps for that
channel. Package-manager installs show the corresponding upgrade command.

Both commands exit with status `1` when the check or download fails, while
`--json` still emits the final error state for callers to inspect. Successful
checks and completed downloads exit with status `0`.

The macOS app is not notarized; first-launch approval steps are in
[Desktop apps](/docs/guides/tray).

<Aside type="caution" title="Downloads do not install themselves">
For a direct install, the update check downloads and checks the release asset.
You still install that download manually. Use the command shown by AnyPick for
package-managed installs or for reinstalling a local `.deb` or `.rpm` file.
</Aside>


## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Operational failure |
| `2` | Invalid usage — missing client or source, bare `use` without a TTY |
| `3` | Not found |
| `4` | Auth required |
| `5` | Capability conflict, unsupported transport, or no binding |
| `6` | Health failure |
| `7` | Missing required dependency, such as an external proxy binary |
| `8` | Malformed or untrusted import envelope |
| `9` | Import exceeds size or file-count limits |
| `130` | Cancelled with SIGINT |

## Environment variables

### AnyPick

| Variable | Effect |
| --- | --- |
| `ANYPICK_HOME` | Data directory. Default `~/.anypick` |
| `ANYPICK_LANG` | Display language (`en`, `zh-CN`, `es`, `fr`, `de`, `ja`, `ko`, `pt-BR`, or `vi`). Defaults to the process locale (`LC_ALL`, `LC_MESSAGES`, or `LANG`; Windows uses the preferred UI language); unsupported locales and untranslated messages fall back to English |
| `ANYPICK_SECRET` | Credential value for `add account` / `add <provider>`, so it is not visible in the process listing |
| `ANYPICK_NO_PLUGINS=1` | Skip loading plugins entirely |
| `NO_COLOR` | Drop all color; glyphs still carry state |

### Provider overrides

| Variable | Effect |
| --- | --- |
| `GEMINI_API_KEY`, `GOOGLE_API_KEY` | Live Gemini API key read by `add account gemini --current` |
| `GEMINI_API_KEY_UPSTREAM` | Override the Gemini API-key upstream base URL |
| `GEMINI_CODE_ASSIST_UPSTREAM` | Override the Gemini Code Assist endpoint |
| `GEMINI_CLI_HOME`, `GEMINI_CONFIG_DIR` | Gemini config-dir resolution (`GEMINI_CLI_HOME` wins, matching the CLI) |
| `CLAUDE_BINARY`, `CODEX_BINARY`, `KIRO_BINARY`, `GROK_BINARY` | Launch a specific client binary |
| `KIROLINK_BIN` | Path to an external `kirolink` binary |
| `WORKBUDDY_BASE_URL` | Override the WorkBuddy/CodeBuddy API base |
| `CLINE_API_BASE_URL`, `CLINE_WORKOS_CLIENT_ID` | Cline API/WorkOS overrides (the client id is public; it overrides the built-in default) |
