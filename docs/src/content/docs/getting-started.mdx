AnyPick answers one everyday question:

> **Which login should Claude Code or Codex use right now?**

You already pay for providers. You already use coding tools. AnyPick snapshots
those logins, starts a local translator when the tools speak different
protocols, and writes the client config — so you pick once in **Apps** instead
of editing files by hand.

## Install a release

Install the CLI from the latest
[GitHub Release](https://github.com/outof0/anypick/releases/latest) with the
package manager for your platform:

```bash
# macOS
brew install outof0/tap/anypick

# Linux, or any OS with Node 18+ (downloads the matching native CLI on first run)
npm install -g anypick
```

```powershell
# Windows
scoop bucket add outof0 https://github.com/outof0/scoop-bucket
scoop install anypick
```

Desktop apps (`.dmg`, `.deb`, `.rpm`, AppImage, `.msi`, `.exe`) and
checksum-listed CLI tarballs are attached to every
[release](https://github.com/outof0/anypick/releases/latest). Check the install
with `anypick --version`, then run `anypick doctor`.

## Open Apps

The native macOS target opens its regular main window automatically. Its
menu-bar quick panel is part of the same app and remains available when the main
window is closed.

For the terminal workflow:

```bash
anypick tui
```

You land on **Apps**:

```
 anypick / apps

  Routes for Claude Code and Codex
 › Claude        not connected                     ○ not set
   Codex         not connected                     ○ not set
 ────────────────────────────────────────────────────────────────────────
 Connect Claude
 enter to build a route
 enter connect app a accounts g gateways p proxies d diagnose
```

Only **Claude Code**, **Codex**, **OpenCode**, **ZCode**, **`dsh`**,
**`commandcode`**, **`pi`** and **`omp`** appear here — they can be pointed at
almost any saved source. Other tools switch their own logins under Accounts.

Three habits that make the UI safe for non-experts:

- **The line under the rule is what <kbd>enter</kbd> will do.** Read it first.
- **The footer is the whole keymap.** No hidden menus.
- **Nothing is saved until a preview says so.** You can always <kbd>esc</kbd>
  back.

The command examples below show AnyPick's CLI grammar. Install the CLI from the
checksum-listed archives on the GitHub Release, or through the thin npm
launcher with `npm install --global anypick` (Node 18+; downloads the matching
native CLI on first run); you can also run the same arguments from this
checkout with `make run ARGS="…"`; for example, `make run ARGS="list accounts"`
(or build once with `make build` and run `./src/go/bin/anypick-dev …`
directly).

Full walkthrough of source → models → preview:
[Terminal UI · Apps](/docs/guides/terminal-ui#build-a-route-the-main-flow).

## Save a login once

AnyPick can start a provider-owned browser sign-in; it does not implement or
imitate the provider's OAuth flow itself.

In the UI: <kbd>a</kbd> **Accounts** → <kbd>a</kbd> **add**. Or:

<Steps>
<Step title="Add the login">
```bash
anypick add account codex --new --name personal
# opens Codex browser Auth and saves the result

# If Codex is already signed in, snapshot it instead:
anypick add account codex --current --name personal
```
</Step>
<Step title="See it listed">
```bash
anypick list accounts
```
</Step>
</Steps>

The pair `provider/name` (for example `codex/personal` or `grok/work`) is the
**source** you will attach to an app.

<Aside type="tip" title="Second login on the same provider">
`anypick add account codex --new --name work` stashes the current credential,
opens the provider's browser Auth, saves the result, and keeps the first account
saved. Official Auth is preferred; provider-declared community methods remain
selectable.
</Aside>

## Connect an app (Apps UI)

Back on **Apps** (press <kbd>esc</kbd> until you see `anypick / apps`):

1. Highlight **Claude** or **Codex**.
2. Press <kbd>enter</kbd> (**connect app**).
3. Pick a source:
   - **Native accounts** — same brand as the app (simple switch).
   - **Gateways & proxies** — Grok, OpenRouter, Gemini proxy, pools, …
   - **Saved setups** — a preset you saved earlier.
4. If asked, choose models (Claude can set default / sonnet / opus / haiku).
5. Read the **preview** — what will be written and which proxy starts.
6. Press <kbd>enter</kbd> to activate.

When you return to Apps the row should show **● ready** with
`source · model`.

That is the whole product for day-to-day use. Open the coding tool as usual.

## Same steps as commands (optional)

Scripts and CI use the same operations without the UI:

```bash
anypick use codex --with codex/personal
anypick run codex
```

Cross-provider example — Claude on a Grok account (proxy starts automatically):

```bash
anypick add account grok --current --name work
anypick use claude --with grok/work
anypick run claude
```

API key instead of a login — register a **gateway**, then pick it in Apps or
pass it to `--with`:

```bash
anypick add gateway openrouter-work \
  --provider openrouter \
  --endpoint https://openrouter.ai/api/v1 \
  --api-key "$OPENROUTER_API_KEY" \
  --model anthropic/claude-sonnet-4

anypick use claude --with openrouter-work
```

## After setup: app or terminal

On macOS, the [native app and menu bar](/docs/guides/tray) are the app-first
daily surface. Use the full window for management and the menu-bar quick panel
for route and service actions. Closing the main window leaves the app running;
explicit **Quit AnyPick** stops its bundled service and exits.

The terminal UI remains a separate source-development surface; it does not
own or stop a separately launched native app.

<Aside type="note" title="No TTY, no UI">
Piped or non-interactive runs never open Apps. Bare `anypick` in a script
prints help and exits so nothing hangs waiting for a key.
</Aside>
