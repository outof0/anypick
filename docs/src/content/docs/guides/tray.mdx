AnyPick ships two native front ends over one Go engine (ADR 0020):

| Platform | Front end | Source |
| --- | --- | --- |
| macOS | SwiftUI app with a menu-bar quick panel | `src/macos/` |
| Linux, Windows | Tauri 2 app | `src/tauri/` |

Both are front ends, not engines. Neither reads credentials or owns AnyPick
state: each launches, handshakes with, supervises and shuts down the bundled Go
service, then renders what that service sends it (ADR 0019 §1).

<Aside type="caution" title="Install from the release channel">
GitHub Releases carry the macOS `.dmg`/`.zip`, Linux and Windows installers,
and CLI archives. The macOS app is not notarized. On first launch, right-click
`AnyPick.app` and choose **Open**, or go to **System Settings → Privacy &
Security → Open Anyway**. You can also run
`/usr/bin/xattr -dr com.apple.quarantine /Applications/AnyPick.app`.
</Aside>

## The app owns its service

The lifecycle is app-first:

```text
AnyPick.app  (or the Tauri app)
├── main window
├── macOS only: menu-bar quick panel
└── bundled Go service, spawned as:
    anypick desktop-service --stdio
```

On launch the app resolves its bundled Go executable relative to its own bundle
and starts it as a child. A version and capability handshake completes before
mutations are enabled. Frames are bounded and stdout is protocol-only.

The app does **not** find the service on `PATH`, connect to a permanent daemon,
or run a Node process. There is no localhost HTTP API, no socket and no gRPC —
any of those needs a new accepted ADR.

Unexpected exits use a bounded restart policy; an incompatible or repeatedly
failing helper puts the UI into a degraded state rather than silently switching
to another engine.

If you remove a client's proxy routing settings or choose another provider in
that client, startup and background proxy maintenance leave that choice alone.
Select a source explicitly in **Apps** to connect the client again.

## macOS

Closing the main window leaves the app and its local services running — the
menu-bar item stays available. Choose **Quit AnyPick** or the quick panel's
**Quit** button to stop the bundled service gracefully and terminate the app.

On Linux and Windows there is no menu-bar item, so closing the window quits the
app and the sidecar with it.

### Main window

The macOS app opens a System Settings-style management window with these sidebar
destinations:

| Destination | Purpose |
| --- | --- |
| **Overview** | Setup progress, installation diagnostics, attention, and service summary |
| **Apps** | Current client routes and source selection |
| **Accounts & APIs** | Saved native logins and API gateways |
| **Proxy Hub** | Unified local endpoint, sources, models, and lifecycle |
| **Proxies** | Per-account translators and their lifecycle |
| **Activity** | Recent events and bounded live logs |
| **Backups** | Export, inspect, import, and restore saved accounts |

App-wide options live in **Settings** (<kbd>⌘,</kbd>), a normal destination in
the main sidebar. The grouped pane contains startup and usage preferences; it
also checks GitHub Releases in **Updates**. Direct-install downloads are saved
and checked against the release checksum, then opened in Finder for manual
installation. Package-manager installs show their upgrade command. Settings
also has an action to show the Getting Started checklist again. Installation
diagnostics are available from Overview.

In **Accounts & APIs → Add Login**, a provider may expose a provider-owned
browser sign-in. AnyPick launches that method and then verifies and saves the
provider's resulting native credential; it does not imitate the provider's OAuth
pages or ask for the account password.

### Menu-bar quick panel

The menu-bar item is a compact panel of the same running app, not a second app.
It is **macOS only**. It can:

- show ready/attention state and search saved accounts or destinations;
- show active app routes and supported usage information;
- switch a supported app to another compatible source;
- expand Proxy Hub and per-account proxy rows for start, stop, and restart;
- open the full AnyPick window or quit the application.

Detailed configuration stays in the main window. The menu-bar icon may show an
attention marker when a route or service needs review. First-run and degraded
states use the same production view hierarchy as the ready state.

### Launch at login

The native Settings toggle uses macOS `SMAppService`. If macOS requires manual
approval, AnyPick directs you to **System Settings → General → Login Items**. It
does not install a custom LaunchAgent from the UI.

## Run from source

**macOS** — requires macOS 14+, Xcode, and a Go launcher able to select the
toolchain pinned by `src/go/go.mod`:

```bash
open src/macos/AnyPick.xcodeproj
```

Select the shared **AnyPick** scheme and Run. A build phase installs the Go
executable at `AnyPick.app/Contents/Helpers/anypick-core`. To build from the
command line instead, use `make build-macos`; `make test-macos` runs the unit tests
and the bundled-helper contract, and `make verify-macos` additionally asserts the
bundle contains no Node runtime.

**Linux and Windows** — from the repository root:

```bash
make run-tauri     # run against the real Go service
make build-tauri   # package for this platform
```

### Previewing UI states without a live account

Set these in the Xcode scheme (**Product → Scheme → Edit Scheme → Run →
Arguments → Environment Variables**), then Run. They drive an in-memory fixture,
so no account or credential is needed:

| Variable | Values |
| --- | --- |
| `ANYPICK_MACOS_FIXTURE` | `ready`, `loading`, `empty`, `error` |
| `ANYPICK_MACOS_DESTINATION` | `overview`, `apps`, `accounts`, `proxyHub`, `proxies`, `activity`, `backups` |
| `ANYPICK_MACOS_FLOW` | `add-account`, `add-gateway`, `tray`, `tray-attention`, `tray-use-with`, `tray-switching`, `tray-recovery`, and others |
| `ANYPICK_MACOS_APPEARANCE` | `system`, `light`, `dark` |
| `ANYPICK_MACOS_RENDER_PATH` | a path — renders the window to a PNG and exits |

Preview the fixture rather than a screenshot of a previous session: a screenshot
freezes the design at the moment it was taken, and the fixture does not.

## Terminal UI

The terminal UI is a separate surface, not part of the app. Build the CLI and
run it:

```bash
make build          # -> src/go/bin/anypick-dev
./src/go/bin/anypick-dev tui
```

or `make run ARGS="tui"`. The TUI talks to the same Go service, but it does not
launch, supervise or shut down a separately opened desktop app; closing the TUI
does not quit the app, and quitting the app does not close the TUI.

## Security boundary

Credentials and per-instance proxy bearer tokens stay in the Go service. Desktop
snapshots carry display-safe state and opaque action identifiers, not raw saved
credentials. The helper's stdio connection is private to its owning app and is
not a documented integration API.

See [Apps & Terminal UI](/docs/guides/terminal-ui) for the terminal workflow and
[Proxies](/docs/guides/proxies) for proxy and Hub behavior.
