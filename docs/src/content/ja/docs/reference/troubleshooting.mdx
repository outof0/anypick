## まず `anypick doctor` を実行します

```bash
anypick doctor
anypick doctor --fix --dry-run
anypick doctor --fix -y
```

`doctor` は、インストール全体を検査します。1 つのクライアントまたはプロバイダーに限定されません。 AnyPick データ ディレクトリ、SQLite データベース、保存されたアカウントとゲートウェイ、ファイル アクセス許可、PID レコード、実行中のプロキシ、および完了しなかった操作ジャーナル エントリをチェックします。

## `--fix` が触れる可能性のあるもの

`--fix` は、6 つのアクションのハード ホワイトリストに基づいて機能します。次のことが可能です。

- 古いPIDファイルを削除する
- 孤立したプロキシを停止します
- `run` によって残された一時的なクライアント オーバーレイを削除します
- AnyPick が所有するパスの権限を修復します
- 派生キャッシュを再構築する
- 中断されたジャーナルのロールバックを完了する

アカウントの切り替え、パッケージのインストール、ネイティブ認証ファイルの操作、バインディングの変更は行われません。許可リスト外のものはすべて **手動のみ** として報告され、その横に提案が印刷されます。端末 UI には同じ分割が表示されます。

一時的なオーバーレイ アクションについては、注意して読んでください。オーバーレイはシステムの一時ディレクトリの下にあるディレクトリであり、その中にはどのプロセスがそれを所有しているかは記録されていないため、`--fix` は経過時間だけで判断し、過去 1 時間に変更されたものはすべて拒否します。長い `anypick run` セッションはその時間を超えて存続する可能性があり、修復により実行中のクライアントの隔離されたホームが削除されます。長時間実行されている `run` が開いている場合は、この操作をスキップし、セッションが終了したらディレクトリを手動で削除してください。リスト上の他のすべてのアクションは、ターゲットに触れる前にターゲットが死んでいることを証明します。

古いロック ファイルは意図的にリストに**含まれていません**。 AnyPick のロックは、保持プロセスが終了するときにカーネルが解放する `flock(2)` 記述子であるため、クラッシュによって削除できる古いものは何も残りません。また、ライブ プロセスがまだ保持しているロック ファイルを削除する「修復」は、アカウントの同時変更が相互に破損するのを防ぐコーディネーターを無効にしてしまいます (ADR 0009)。このページの初期の草案では、この行動が約束されていました。それは存在できません。

<Aside type="tip" title="最初にプレビューする">
`anypick doctor --fix --dry-run` は、ホワイトリストに登録されているどのアクションが実行されるかを正確に出力します。ホワイトリストが抽象的でなくなるように、一度実行する価値があります。
</Aside>

## 終了コードの読み取り

|コード |意味 |通常の原因 |
| --- | --- | --- |
| `1` |操作上の失敗 |コマンド中に予期しないランタイム エラーが発生しました。
| `2` |無効な使用方法 | `--with` または `--current` のない `use`、または不正フラグ |
| `3` |見つかりません |アカウント、ゲートウェイ、プリセット、またはクライアント名が存在しません |
| `4` |認証が必要です |ログインまたは API キーが見つからないか、有効期限が切れています。
| `5` |機能の競合 |ソースがそのクライアントにサービスを提供できないか、バインディングが存在しません。
| `6` |健康障害 |ヘルスチェックに失敗しました |
| `7` |依存関係がありません | `kirolink` などの外部プロキシ バイナリがインストールされていません。
| `8` / `9` |輸入が拒否されました |エクスポート エンベロープが間違っているか、アーカイブが大きすぎます。
| `130` |キャンセルされました | Ctrl+C | を押しました。

## よくある状況

### クライアントは起動しますが、ソースを無視します

実際に何が有効であるかを確認してください。現在のディレクトリ内のプロジェクト バインディングは、グローバル デフォルトよりも優れています。

```bash
anypick current claude
```

古いプロジェクト バインディングが優先されている場合、`anypick unlink claude` はそれを削除します。

### `run` はバインドなしで 5 を終了します

そのクライアントには、一時バインディング、プロジェクトバインディング、またはグローバルバインディングはありません。 1 つを設定します:

```bash
anypick use claude --with grok/work
```

### プロキシが起動しない

ログを確認し、次にポートを確認します。

```bash
anypick proxy status gemini work
anypick proxy logs gemini work --lines 100
anypick proxy config gemini work --port 4131     # move it
```

すでに保持されている構成済みのポートが起動に失敗することはなくなりました。AnyPick はプロキシを空きポートに移動し、永続化し、バインドされたクライアントを書き換えて、移動を警告として報告します。以前のセッションから残ったプロキシは、`anypick proxy stop gemini work` という名前を付けることで停止できます。 「すべてを停止する」という形式はありません。引数なしの `anypick proxy` コマンドは、その使用法を出力します。

### Gemini プロキシがモデルを拒否する

OAuth 専用 Gemini アカウントはクライアントにサインインできますが、プロキシを駆動することはできません。プロキシには、保存されたログインの `.env` に `GEMINI_API_KEY` が必要です。両方のサインインが存在する場合は、プロキシが提供するソースを保存します。

```bash
anypick add account gemini --current --source gemini-cli --name work
anypick add account gemini --current --source antigravity --name work
```

### 保存されたログインとライブ ログインが一致しません

端末 UI はこれに `◐ changed` をマークします。これは、AnyPick がスナップショットを取得した後、プロバイダーの CLI が新しい認証情報を書き込んだことを意味します。新しいものを採用します。

```bash
anypick account refresh codex
```

### 保存された 2 つのアカウントが 1 つのスナップショットを共有します

同じプロバイダーの 2 つの名前が同じ資格情報スナップショットを保持している場合、`anypick doctor` は `duplicate-snapshot` を報告します。それらを切り替えてもログインを変更することはできません。 AnyPick は新しいペアの作成を拒否し、以前に保存されたペアをクリーンアップすることのみを要求します。

```bash
anypick doctor --json                          # exact names, and which to keep
anypick account remove workbuddy/work
```

`anypick doctor` は、保持するアカウントを `keep <provider>/<account>` として示し、削除コマンドを出力します。両方の名前が有効な場合 (一方がアクティブで、もう一方もクライアント バインディングから参照されている場合)、削除コマンドを出力せず、クライアントを 1 つのアカウントに再バインドするよう求めます。これにより、クリーンアップでルートが中断されることはありません。

### macOS でアプリが開かない

macOS アプリは Apple Developer ID ではなくアドホック署名されているため、 Gatekeeper が確認できる公証チケットがありません。初回起動時に、macOS が次のいずれかのメッセージで拒否することがあります。

- 「開発元を検証できないため、"AnyPick.app" は開けません。」
- 「"AnyPick.app" は壊れているため開けません。ゴミ箱に入れる必要があります。」

どちらも、ダウンロードが破損しているという意味ではありません。開く方法は 2 つあり、どちらか 1 つで十分です。

**システム設定から許可する。** 一度アプリを開こうとして警告を閉じ、 **システム設定 → プライバシーとセキュリティ** を開き、**セキュリティ** までスクロールして、AnyPick の項目の横にある **このまま開く** をクリックします。macOS はこの許可を記録するので、バージョンごとに一度だけの手順です。

**隔離属性を削除する。** 絶対パスを使います。

```bash
/usr/bin/xattr -dr com.apple.quarantine /Applications/AnyPick.app
```

絶対パスであることが重要です。`xattr` は Python パッケージの名前でもあり、バージョンマネージャーの shim が `PATH` でシステムのバイナリより前に置くことがあります。そのプログラムには `-r` オプションがないため、パスなしの `xattr -dr` は使用法エラーで終了し、何も削除しません。

Homebrew の cask でインストールしても、この手順は省けません。Homebrew はブラウザーと同じ隔離属性を付け、`--no-quarantine` オプションも削除されたため、初回起動には上記の許可が必要です。

一度アプリが起動すれば、以降の起動やアプリ内アップデートで再び尋ねられることはありません。アップデーターは Go の HTTP クライアントでダウンロードしており、隔離属性をまったく付けないためです。

### UI を閉じた後もプロキシが実行され続ける

ネイティブ アプリのメイン ウィンドウを閉じても、アプリは終了しません。アプリまたはメニューバーのクイック パネルから **Quit AnyPick** を使用して、バンドルされている Go サービスを正常に停止します。

ソース TUI を閉じると、既存の互換性プロセスも変更されないままになります。このチェックアウトから互換性スーパーバイザを停止するには:

```bash
make run ARGS="tray stop"
```

`make run ARGS="proxy stop"` は、実行中のアカウント プロキシを直接停止します。 TUI は、明示的に <kbd>Shift+D</kbd> を押すか、トレイのランタイム画面から起動した場合にのみ、互換性スーパーバイザを起動します。別途起動された `AnyPick.app` は制御されません。

### アクティベーションが途中で失敗しました

変更中のアクティベーション手順は、バックアップ パスとともに操作ジャーナルに記録されるため、アクティベーションが失敗しても、以前の状態 (クライアント構成、ネイティブ認証、および開始したプロキシ) が復元されます。ロールバックが完了する前にプロセスが強制終了された場合は、`anypick doctor --fix` によってプロセスが完了します。

アカウントの切り替えも同じトランザクションです。新しく選択したアカウントをバインドされたクライアントに適用できない場合は、アクティブ ポインタ、クライアント バインディング、および以前のアカウントのプロキシがすべて復元され、エラーがそのことを示します。クライアントが古いプロキシを指している間は、アプリが新しいアクティブなアカウントを要求することは決してありません。

## さらに深く掘り下げる

```bash
anypick --trace use claude --with grok/work    # name each step, no secrets
anypick proxy status <provider> <account>      # live listener state
anypick doctor --json                          # machine-readable findings
```

`--trace` はアクティベーション プランを段階的に出力します。通常、どの段階が失敗したかを確認するにはこれで十分です。 `--dry-run` と組み合わせると、実行せずにプランを表示できます。
