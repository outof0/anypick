コマンド名は`anypick`です。 GitHub リリースからチェックサムリスト付きアーカイブをダウンロードするか、`npm install --global anypick` を使用して Thin npm ランチャーをインストールします (ノード 18 以降。初回実行時に一致するネイティブ CLI をダウンロードします)。開発中は、`make run ARGS="…"` を使用してチェックアウトから同じコマンド ツリーを実行します。たとえば、`make run ARGS="list accounts"`。

ネイティブ macOS アプリケーションは、アプリが所有する別のターゲットです。バンドルされている Go サービス自体を起動するため、この CLI を親にする必要はありません。

## グローバルフラグ

すべてのコマンドで有効です。

|旗 |効果 |
| --- | --- |
| `-V, --version` |バージョンを出力して終了 |
| `--json` |機械可読出力 |
| `-v, --verbose` |詳細なログ |
| `-q, --quiet` |最小出力 |
| `--dry-run` |計画を印刷します。何も書かない |
| `--reveal` |秘密を表示 — 危険 |
| `--no-input` | TTY であってもプロンプトを表示しない |
| `-y, --yes` |破壊的な確認をスキップする |
| `--trace` |内部ステップ名をシークレットなしで出力します。
| `--tui` |この実行のためにターミナル UI を開きます |
| `--tray` |このソース CLI 実行用の互換性トレイの表面を選択します。

## バインディング

```bash
anypick use <client> --with <source> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick use codex --with <source> --profile <name> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick run <client> (--with <source>|--profile <name>) [--model <id>] -- <args…>
anypick codex profile login <name> [--auth-method <id>] [--source <id>]
anypick codex profile list
anypick codex profile show <name>
anypick codex profile remove <name> [--yes]
anypick current <provider>
anypick models <client> [--with <source>]
anypick link <client> [--with <source>] [--model <id>] [--allow-foreign-config]
anypick unlink [client]
anypick reset [client]
```

|コマンド |説明 |
| --- | --- |
| `use` |クライアントがデフォルトで使用するものを設定します (`--with` は必須です) |
| `run` |効果的なバインディングを使用してクライアントを起動する |
| `current` | 1 つのプロバイダーの有効なバインディングを表示する |
| `models` |バインドされたソースが公開するモデル ID をリストします。
| `link` / `unlink` |現在のディレクトリのプロジェクト スコープのバインディング。 `--with` を使用しない `link` は、保存されているグローバル仕様を再適用します。
| `reset` |クライアントの AnyPick 管理構成を削除する |

`--with` は、アカウント (`grok/work`)、ゲートウェイ名、プール (`pool:gemini`)、プロキシ ハブ (`hub:default`)、またはプリセット (`@work-stack`) を受け入れます。 `--transport` は、プランナーに選択させるのではなく、ルート ポリシーを固定します。

#### AnyPick が所有していないクライアント構成

AnyPick は他のツールの設定ファイルを書き込むため、書き込んだことが証明できない値の置き換えを拒否します。 `~/.claude/settings.json` または Codex 設定がすでに独自のログインまたはエンドポイントを指している場合、`use` は `CLIENT_CONFIG_FOREIGN` で失敗し、問題のファイルとキーに名前が付けられます。設定はバイト同一のままです。

`--allow-foreign-config` は明確な答えです。現在のファイルを `$ANYPICK_HOME/recovery/clients/<client>/` にバックアップし、それらの値を置き換えます。同意は実行ごとに行われ、永続化されることはありません。デスクトップ アプリでは、フラグの代わりに **AnyPick で管理** ボタンを使用して同じ質問をします。 AnyPick がすでに管理しているクライアント (ループバック プロキシ エンドポイント、または AnyPick の管理対象マーカーを保持する設定) は、確認なしに更新されます。

### 名前付き Codex プロファイル

`--profile` は Codex に安定したネイティブ プロファイル名を与え、AnyPick はその背後にソースを保存します。これは、1 つのシェルまたはスクリプトに複数の保存されたルートが必要な場合に便利です。各プロファイルには独自の `CODEX_HOME`、`<name>.config.toml`、および `auth.json` があります。プロキシベースのプロファイルには、所有者専用の環境ファイルも取得されます。

保存された Codex アカウントの場合、`auto` はネイティブ プロファイル ホームを使用し、そのアカウントの保存された `auth.json` をコピーします。デスクトップ アプリのライブ `CODEX_HOME` には影響しません。デスクトップ ログインを切り替えずにアカウントとプロファイルを作成するには、`profile login` を使用します。

```bash
anypick codex profile login work
anypick use codex --with codex/work --profile work --model gpt-5.6
anypick use codex --with openrouter-work --profile gateway
anypick use codex --with hub:default --profile hub-work
```

`profile login` は、`CODEX_HOME=$ANYPICK_HOME/clients/codex/profiles/work/codex-home` を使用して公式 Codex ログインを実行するため、ブラウザ フローはアカウント B をそこに書き込みます。次に、AnyPick は同じファイルを `codex/work` スナップショットとして保存し、デスクトップのアクティブ ポインタを復元します。代わりにアカウントベースのプロキシを使用するには、それを有効にして `--transport proxy` を固定します。

```bash
anypick proxy enable codex work
anypick use codex --with codex/work --profile work-proxy --transport proxy
```

デフォルトの Codex CLI 設定は、`--profile` なしで同じルートを受け入れます。

```bash
anypick use codex --with codex/work --transport proxy
anypick use codex --with hub:default
```

分離された Codex CLI プロセスを通じてプロファイルを実行するには、次を使用します。

```bash
anypick run codex --profile personal -- exec --help
anypick codex profile list
```

生の呼び出しの場合は、`anypick codex profile show <name>` によって出力される `launch` コマンドを使用します。プロファイル固有の `CODEX_HOME` を明示的に設定します。プロキシベースのプロファイルは、所有者専用の env ファイルもソースとします。その env ファイルを印刷またはコミットしないでください。このファイルにはローカル プロキシの資格情報が含まれています。ハブでバックアップされたプロファイルには個別のルート トークンがあるため、1 つのプロファイルをアクティブ化しても、デフォルト ルートや別のプロファイルが無効になることはありません。これらのコマンドは Codex CLI を設定します。 Codex Desktop は独自のサインイン アカウントを保持し、CLI の `CODEX_HOME` に従いません。

`anypick codex profile remove <name>` は、ルートと、AnyPick が生成したファイル (プロファイル設定、そのモデル カタログ、およびその env ファイル) を削除します。プロファイルのプライベート `CODEX_HOME` はそのまま残るため、同じ名前で再度サインインすると、それが再利用されます。プロファイルが指す *アカウント* を削除することは異なります。`anypick account remove codex work` は、そのアカウントにバインドされている名前付きプロファイル (資格情報ホームを含む) も削除し、結果でそれらに名前を付けます。ゲートウェイ、ハブ、プール、または別のアカウントを指すプロファイルは操作されません。 AnyPick は、次回の起動時に以前の削除で残ったプロファイルをスイープし、それまでに `anypick doctor` がそれらを報告します。

<Aside type="caution" title="非インタラクティブな使用">
`use <client>` には `--with` が必要です。これがなければソースを導出するものが何もないため、コマンドは推測する代わりに `2` を終了します。
</Aside>

## 在庫

```bash
anypick list [providers|accounts]   # default: providers
anypick providers
anypick clients
```

`ls` エイリアスや `list gateways|clients|presets` 形式はありません。ゲートウェイ、プリセット、プラグインには、それぞれ以下の独自のコマンド ファミリがあります。

## ソースの追加

```bash
anypick add account <provider> --name <name> [--current|--new] [--source <id>] [--force]
anypick add account <provider> --new --name <name> [--auth-method <id>] [--source <id>]
anypick add account <provider> --name <name> --credential <kind> --secret [--option profile=<id>] [--region <region>]
anypick add gateway <name> --provider <id> [--endpoint url]
    [--api-key [key] | --api-key-env <var> | --secret <key>]
    [--model <id>] [--models <role=id>]
```

`--current` は、現在有効なログインのスナップショットを作成します。 `--new` は、利用可能なプロバイダー所有のブラウザー サインインを使用し、その結果得られるネイティブ資格情報を保存します。それ以外の場合は、現在のログインを隠し、手動の続きを出力します。公式メソッドが優先されますが、`--auth-method <id>` はコミュニティ メソッドを含め、プロバイダーが宣言する任意のメソッドを選択できます。 `--source <id>` は、マルチソース プロバイダーの明示的なネイティブ ストアを選択します。 `--credential <kind>` (covers `--api-key` for compatible providers) plus `--secret`, `--api-key`, or a bare `--api-key` prompt supplies an API-key credential; `--profile` または `--option profile=<id>` はエンドポイント プロファイルを選択し、`--region` は Kiro API キーのクラウド リージョンです。 `--secret` 値を省略してマスクされたプロンプトを使用するか、`ANYPICK_SECRET` を渡します。

## アカウント

```bash
anypick account list [provider]
anypick account refresh [provider [name]] [--all]
anypick account remove <provider> <name> [--yes]
anypick account export <provider> <name> [--out <file>]   # -o <file>; defaults to ~/.anypick/exports/*.json
anypick account export [provider] --all [--out <file>] [--overwrite]
anypick account import <provider> <name> <file.json> [--force]   # or -i <file.json>
anypick account import <file.json> [<file2.json> …] [--force]
```

`refresh` は、保存されたアカウントへのプロバイダーの現在のライブ ログインを採用します。プロバイダーがない場合、保存されているすべてのアカウントが試行されます。プロバイダー (およびオプションで名前) を使用すると、それらだけが更新されます。あるアカウントに別のアカウントのスナップショットを与える更新は拒否されます (1 つのログインは 1 つのアカウントのままです)。そのため、プロバイダー全体を更新しても、個別のログインを現在のライブログインに黙って折りたたむことはできません。 `rm` エイリアスはありません。

## ゲートウェイ

```bash
anypick gateway add <name> --provider <id> [--endpoint url]
    [--api-key [key]|--api-key-env <var>|--secret <key>]
    [--model <id>] [--models <role=id>]
anypick gateway list
anypick gateway show <name>
anypick gateway edit <name> [--endpoint url] [--model id] [-m id] [--api-key key]
anypick gateway remove <name>
```

`show` は、グローバル `--reveal` を渡さない限り、API キーをマスクします。 `edit` は、保存されたキーを置き換える `--api-key` と、`--model` の短縮形として `-m` を受け入れます。

## プリセット

```bash
anypick preset list
anypick preset show <name>
anypick preset remove <name>
```

ここでは、プリセット名は `@` なしで書かれています。 `@` プレフィックスは、`--with` でプレフィックスを参照する方法のみです。

## プロキシ

```bash
anypick proxy enable|disable <provider> <account> [--port N]
anypick proxy start|stop|status|token <provider> <account>
anypick proxy config <provider> <account> [--port N]
anypick proxy restart <provider> <account>
anypick proxy logs <provider> <account> [--lines N] [--follow]
```

`enable`/`config` の `--port` はポートを固定します。それ以外の場合は、最初の空きポートが使用されます。 `token` は、プロキシの認証トークン/API キーを印刷または回転 (`--rotate`) します。 `logs` はデフォルトで最後の 50 行を印刷します。

実行中のプロキシでローテーションすると、AnyPick は新しいキーが受け入れられ、以前のキーが拒否されることを確認してから、そのアカウントにバインドされたすべてのクライアント（プールのプライマリーアカウントの場合はプールのクライアントも）を更新します。設定を AnyPick のルートから外したクライアントは、`--allow-foreign-config` を付けない限り変更されません。確認に失敗しても、新しいキーは理由とともに表示されます。実行中のプールの最初のメンバーをローテーションしても、プールは動き続けます。

### プール

```bash
anypick proxy pool status <provider>
anypick proxy pool enable <provider> [--strategy failover|round-robin|soonest-reset]
    [--mode single|multi] [--port N] [-p N] [+account|-account ...]
anypick proxy pool member <provider> <account> <on|off>
anypick proxy pool start <provider>
anypick proxy pool stop <provider>
anypick proxy pool disable <provider>
```

`enable` は、1 回の呼び出しで `+account` メンバーを追加し、`-account` メンバーを一時停止します。デフォルトの戦略は `failover`、デフォルトのモードは `multi` です。 `round-robin` では、各リクエストは次の対象メンバーから開始されます。 `failover` の場合、最後に応答したアカウントは拒否されるまでサービスを提供し続けます。いずれの場合でも、クォータ クラスの障害が発生すると、リクエストは次のメンバーに移されます。

### プロキシハブ

```bash
anypick proxy hub status <name>
anypick proxy hub enable <name> [--host <host>] [--port N] [-p N]
    [--strategy failover|round-robin|soonest-reset] [--start]
anypick proxy hub source <name> <provider> <account>
anypick proxy hub owner <name> <model> <provider>/<account>
anypick proxy hub preview <name>
anypick proxy hub start <name>
anypick proxy hub stop <name>
anypick proxy hub combo add <name> <combo> <provider/account=model>...
anypick proxy hub combo list <name>
anypick proxy hub combo remove <name> <combo>
```

`source` 切り替え: 現在のソースが削除され、存在しないソースが追加されます (アカウント名が必要です)。 `--strategy round-robin` により、ハブは各モデルを 1 つに固定するのではなく、モデルを提供できる有効なアカウント (モデルが解決されるプロバイダーのアカウント) 全体に分散します。フラグがない場合は、現在のモードが維持されます。少なくとも 1 つのソースを有効にした後、`--with hub:<name>` でバインドします。 `owner` は、2 つのソースが同じモデル ID をアドバタイズする場合にどちらのアカウントが勝つかを選択します。 `preview` はカタログを更新し、ルートと競合を出力します。

`combo` は、ハブがモデル ID として提供する名前付きのフォールバックチェーンを管理します。[プロキシ](/ja/docs/guides/proxies) を参照してください。

## プラグイン

```bash
anypick plugin list
anypick plugin add <dir>
anypick plugin enable <name>
anypick plugin disable <name>
anypick plugin trust <name>
anypick plugin remove <name>
```

`add` はローカル ディレクトリを **無効** でインストールします。 `enable` は信頼の決定とプロンプトです。 TTY がない場合は、グローバル `-y` が必要です。 `trust` は、プラグインのコードが変更された後、パッケージ ダイジェストを再固定します。 [プラグイン](/ja/docs/guides/plugins)を参照してください。

## ソース CLI サーフェスと互換性スーパーバイザ

```bash
anypick tui
anypick tray
anypick start
anypick status
anypick stop
```

`anypick tui`は常に[アプリ/ターミナルUI](/ja/docs/guides/terminal-ui)を開きます。 `tray` コマンド ファミリーは Go エンジンによって実装されます (TypeScript ツリーとそのトレイ サーフェスはもう存在しません)。 `anypick tray` は互換性スナップショットを印刷し、`start`、`status`、および`stop` は、互換性スーパーバイザーとそれが所有するプロキシを制御します。

これらのコマンドは、ネイティブ アプリの所有権を定義しません。 macOS アプリは、`Contents/Helpers/anypick-core` を解決して開始し、メニュー バーのクイック パネルを同じアプリケーション内に保持し、明示的なアプリの終了でヘルパーを停止します。 [macOS アプリとメニュー バー](/ja/docs/guides/tray) を参照してください。

## 使用履歴

```bash
anypick usage [--since 7d|24h|2026-10-01] [--by model|account|provider|day] [--json]
```

実行中のプロキシ、プール、Proxy Hub が処理したトークンを、API 定価での費用見積もりとともに表示します。`--since` の既定は `7d` で、履歴は 90 日間保持されます。 `--by` の既定は `model` です。何が記録されるか、見積もりの算出方法、価格の追加方法は [使用量とコスト](/ja/docs/guides/usage) にあります。

## 更新チェック

```bash
anypick update
anypick update --json
```

このアドバイザリ チェックでは、実行中のバージョンと最新の GitHub リリースを比較します。利用可能なインストール ルートを出力します。インストールは変わりません。このガイダンスでは、リリース ページ、利用可能なパッケージ マネージャー、またはソース チェックアウトを示しています。

```bash
git pull && make build
```

リリースが公開されるまで、チェックでは `no published release yet` がレポートされ、ソース ワークフローが示されます。 `--json` は、現在および最新のバージョンを返します。

```bash
anypick update --json
```

```json
{ "current": "1.0.0", "latest": "1.1.0" }
```

更新エンジンには、明示的なチェックおよびダウンロード コマンドもあります。 macOS の [**設定] → [アップデート]** ペインでも同じコマンドを使用します。

```bash
anypick update check --json
anypick update download --json
```

`check` は、検出されたチャネルのアップデート状態とインストールアクションを報告します。 `download` は、直接インストールされたアセットを AnyPick のユーザー キャッシュにフェッチし、そのリリースのチェックサム ファイルに対して SHA-256 をチェックします。インストールされているアプリを置き換えたり、再起動したりすることはありません。 [設定] で [**Finder に表示**] を選択すると、ダウンロードされたファイルが開くので、そのチャネルの通常の手順を使用してインストールできます。パッケージ マネージャーのインストールでは、対応するアップグレード コマンドが表示されます。

macOS アプリは公証されていません。初回起動時の承認手順は [デスクトップ アプリ](/ja/docs/guides/tray) にあります。

<Aside type="caution" title="ダウンロード自体はインストールされません">
直接インストールの場合、更新チェックではリリース アセットをダウンロードしてチェックします。そのダウンロードを手動でインストールすることになります。パッケージ管理によるインストール、またはローカルの `.deb` または `.rpm` ファイルの再インストールには、AnyPick によって示されるコマンドを使用します。
</Aside>

## 終了コード

|コード |意味 |
| --- | --- |
| `0` |成功 |
| `1` |操作上の失敗 |
| `2` |無効な使用法 - クライアントまたはソースが欠落しており、TTY なしの裸の `use` |
| `3` |見つかりません |
| `4` |認証が必要です |
| `5` |機能の競合、サポートされていないトランスポート、またはバインドがない |
| `6` |健康障害 |
| `7` |外部プロキシ バイナリなどの必要な依存関係が欠落しています。
| `8` |不正な形式または信頼できないインポート エンベロープ |
| `9` |インポートがサイズまたはファイル数の制限を超えています。
| `130` | SIGINT でキャンセルされました |

## 環境変数

### エニーピック

|変数 |効果 |
| --- | --- |
| `ANYPICK_HOME` |データディレクトリ。デフォルト `~/.anypick` |
| `ANYPICK_LANG` |表示言語 (`en`、`zh-CN`、`es`、`fr`、`de`、`ja`、 `ko`、`pt-BR`、または `vi`)。デフォルトはプロセス ロケール (`LC_ALL`、`LC_MESSAGES`、または `LANG`、Windows は優先 UI 言語を使用します)。サポートされていないロケールと未翻訳のメッセージは英語に戻ります。
| `ANYPICK_SECRET` | `add account` / `add <provider>` の資格情報の値なので、プロセス リストには表示されません。
| `ANYPICK_NO_PLUGINS=1` |プラグインの読み込みを完全にスキップする |
| `NO_COLOR` |すべての色をドロップします。グリフは依然として状態を保持します。

### プロバイダーのオーバーライド

|変数 |効果 |
| --- | --- |
| `GEMINI_API_KEY`、`GOOGLE_API_KEY` | `add account gemini --current` によって読み取られた Live Gemini API キー |
| `GEMINI_API_KEY_UPSTREAM` | Gemini API キーのアップストリーム ベース URL をオーバーライドします。
| `GEMINI_CODE_ASSIST_UPSTREAM` | Gemini Code Assist エンドポイントをオーバーライドする |
| `GEMINI_CLI_HOME`、`GEMINI_CONFIG_DIR` | Gemini config-dir 解決 (`GEMINI_CLI_HOME` が勝ち、CLI と一致) |
| `CLAUDE_BINARY`、`CODEX_BINARY`、`KIRO_BINARY`、`GROK_BINARY` |特定のクライアント バイナリを起動する |
| `KIROLINK_BIN` |外部 `kirolink` バイナリへのパス |
| `WORKBUDDY_BASE_URL` | WorkBuddy/CodeBuddy API ベースをオーバーライドする |
| `CLINE_API_BASE_URL`、`CLINE_WORKOS_CLIENT_ID` | Cline API/WorkOS オーバーライド (クライアント ID は公開されており、組み込みのデフォルトをオーバーライドします) |
