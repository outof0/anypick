AnyPick は、1 つの Go エンジン上で 2 つのネイティブ フロント エンドを出荷します (ADR 0020)。

|プラットフォーム |フロントエンド |出典 |
| --- | --- | --- |
| macOS |メニューバークイックパネルを備えた SwiftUI アプリ | `src/macos/` |
| Linux、Windows | Tauri 2 アプリ | `src/tauri/` |

どちらもエンジンではなくフロントエンドです。どちらも認証情報を読み取ったり、AnyPick 状態を所有したりすることはありません。それぞれがバンドルされた Go サービスを起動、ハンドシェイク、監視およびシャットダウンし、そのサービスが送信したものをレンダリングします (ADR 0019 §1)。

<Aside type="caution" title="リリース チャネルからインストールする">
GitHub リリースには、macOS `.dmg`/`.zip`、Linux および Windows インストーラー、および CLI アーカイブが含まれています。 macOS アプリは公証されていません。初回起動時に、`AnyPick.app` を右クリックして **開く** を選択するか、**システム設定 → プライバシーとセキュリティ → とにかく開く** に移動します。 `/usr/bin/xattr -dr com.apple.quarantine /Applications/AnyPick.app` を実行することもできます。
</Aside>

## アプリは独自のサービスを所有します

ライフサイクルはアプリファーストです。

```text
AnyPick.app  (or the Tauri app)
├── main window
├── macOS only: menu-bar quick panel
└── bundled Go service, spawned as:
    anypick desktop-service --stdio
```

起動時に、アプリはバンドルされた Go 実行可能ファイルを独自のバンドルに関連付けて解決し、子として起動します。バージョンと機能のハンドシェイクは、ミューテーションが有効になる前に完了します。フレームは制限されており、標準出力はプロトコルのみです。

アプリは、`PATH` でサービスを見つけたり、永続デーモンに接続したり、ノード プロセスを実行したりしません**。 localhost HTTP API、ソケット、gRPC はありません。これらのいずれにも、新しく承認された ADR が必要です。

予期しない終了では、制限付き再起動ポリシーが使用されます。互換性のないヘルパーや繰り返し失敗するヘルパーは、別のエンジンに自動的に切り替えるのではなく、UI を劣化状態にします。

## macOS

メイン ウィンドウを閉じると、アプリとそのローカル サービスは実行されたままになります。メニュー バーの項目は使用可能なままになります。 [**Quit AnyPick**] またはクイック パネルの [**Quit**] ボタンを選択して、バンドルされたサービスを正常に停止し、アプリを終了します。

Linux と Windows にはメニューバー項目がないため、ウィンドウを閉じるとアプリとサイドカーも終了します。

### メインウィンドウ

macOS アプリでは、次のサイドバーの宛先を含むシステム設定スタイルの管理ウィンドウが開きます。

|目的地 |目的 |
| --- | --- |
| **概要** |セットアップの進行状況、インストール診断、注意事項、およびサービスの概要 |
| **アプリ** |現在のクライアント ルートとソースの選択 |
| **アカウントと API** |保存されたネイティブ ログインと API ゲートウェイ |
| **プロキシ ハブ** |統合されたローカル エンドポイント、ソース、モデル、ライフサイクル |
| **プロキシ** |アカウントごとの翻訳者とそのライフサイクル |
| **アクティビティ** |最近のイベントと限定されたライブ ログ |
| **バックアップ** |保存されたアカウントをエクスポート、検査、インポート、復元する |

アプリ全体のオプションは **設定** (<kbd>⌘,</kbd>) にあり、メイン サイドバーの通常の場所です。グループ化されたペインには、起動設定と使用方法の設定が含まれています。また、**アップデート**で GitHub リリースもチェックします。直接インストールのダウンロードは保存され、リリース チェックサムと照合されてから、手動インストール用に Finder で開かれます。パッケージ マネージャーのインストールでは、アップグレード コマンドが表示されます。設定には、「はじめに」チェックリストを再度表示するアクションもあります。インストール診断は「概要」から利用できます。

**[アカウントと API] → [ログインの追加]** では、プロバイダーがプロバイダー所有のブラウザー サインインを公開する場合があります。 AnyPick はそのメソッドを起動し、プロバイダーの結果のネイティブ資格情報を検証して保存します。プロバイダーの OAuth ページを模倣したり、アカウントのパスワードを要求したりすることはありません。

### メニューバーのクイックパネル

メニューバー項目は、2 番目のアプリではなく、同じ実行中のアプリのコンパクトなパネルです。 **macOS のみ**です。次のことが可能です。

- 準備完了/注意状態を表示し、保存されたアカウントまたは宛先を検索します。
- アクティブなアプリのルートとサポートされている使用状況情報を表示します。
- サポートされているアプリを別の互換性のあるソースに切り替えます。
- プロキシ ハブとアカウントごとのプロキシ行を展開して、開始、停止、再起動を行います。
- AnyPick ウィンドウ全体を開くか、アプリケーションを終了します。

詳細な設定はメイン ウィンドウに残ります。ルートまたはサービスの確認が必要な場合、メニュー バー アイコンにアテンション マーカーが表示される場合があります。初回実行状態と劣化状態では、準備完了状態と同じ運用ビュー階層が使用されます。

### ログイン時に起動

ネイティブ設定トグルは macOS `SMAppService` を使用します。 macOS で手動承認が必要な場合、AnyPick は **[システム設定] → [一般] → [ログイン項目]** に移動します。 UI からカスタム LaunchAgent はインストールされません。

## ソースから実行

**macOS** — macOS 14+、Xcode、および `src/go/go.mod` で固定されたツールチェーンを選択できる Go ランチャーが必要です。

```bash
open src/macos/AnyPick.xcodeproj
```

共有 **AnyPick** スキームを選択して実行します。ビルドフェーズでは、Go 実行可能ファイルが `AnyPick.app/Contents/Helpers/anypick-core` にインストールされます。代わりにコマンド ラインからビルドするには、`make build-macos` を使用します。 `make test-macos` は単体テストとバンドル ヘルパー コントラクトを実行し、`make verify-macos` はさらにバンドルにノード ランタイムが含まれていないことをアサートします。

**Linux および Windows** — リポジトリ ルートから:

```bash
make run-tauri     # run against the real Go service
make build-tauri   # package for this platform
```

### ライブアカウントを使用しない UI 状態のプレビュー

これらを Xcode スキーム (**Product → Scheme → Edit Scheme → Run → Arguments → Environment Variables**) に設定し、実行します。これらはメモリ内フィクスチャを駆動するため、アカウントや認証情報は必要ありません。

|変数 |値 |
| --- | --- |
| `ANYPICK_MACOS_FIXTURE` | `ready`、`loading`、`empty`、`error` |
| `ANYPICK_MACOS_DESTINATION` | `overview`、`apps`、`accounts`、`proxyHub`、`proxies`、`activity`、 `backups` |
| `ANYPICK_MACOS_FLOW` | `add-account`、`add-gateway`、`tray`、`tray-attention`、`tray-use-with`、`tray-switching`、 `tray-recovery` 他 |
| `ANYPICK_MACOS_APPEARANCE` | `system`、`light`、`dark` |
| `ANYPICK_MACOS_RENDER_PATH` |パス — ウィンドウを PNG にレンダリングして終了します。

前のセッションのスクリーンショットではなく、フィクスチャをプレビューします。スクリーンショットでは、撮影した瞬間にデザインがフリーズしますが、フィクスチャではフリーズしません。

## ターミナル UI

ターミナル UI はアプリの一部ではなく、別個のサーフェスです。 CLI を構築して実行します。

```bash
make build          # -> src/go/bin/anypick-dev
./src/go/bin/anypick-dev tui
```

または`make run ARGS="tui"`。 TUI は同じ Go サービスと通信しますが、個別に開かれたデスクトップ アプリの起動、監視、シャットダウンは行いません。 TUI を閉じてもアプリは終了しません。また、アプリを終了しても TUI は終了しません。

## セキュリティ境界

資格情報とインスタンスごとのプロキシベアラー トークンは Go サービスに残ります。デスクトップ スナップショットには、保存された生の資格情報ではなく、ディスプレイ セーフ状態と不透明なアクション識別子が含まれます。ヘルパーの stdio 接続は、その所有アプリに対してプライベートであり、文書化された統合 API ではありません。

ターミナルのワークフローについては [アプリとターミナル UI](/ja/docs/guides/terminal-ui) を、プロキシとハブの動作については [プロキシ](/ja/docs/guides/proxies) を参照してください。
