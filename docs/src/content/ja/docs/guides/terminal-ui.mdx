`anypick` (または `anypick tui`) を実行します。 **アプリ**にアクセスします。その画面が製品です。各コーディング ツールに対する 1 つの質問に答えます。

> **Claude Code / Codex / ZCode / dsh / commandcode / pi / omp は今何を使用すべきですか?**

他のすべて (アカウント、ゲートウェイ、プロキシ) は、その答えを提供するために存在します。

```bash
anypick
```

## アプリの概要

```
 anypick / apps

  Routes for Claude Code and Codex
 › Claude        grok/work · grok-code-fast-1       ● ready
   Codex         not connected                     ○ not set
 ──────────────────────────────────────────
 Claude uses grok/work
 model grok-code-fast-1 · enter to preview a different route
 enter change route a accounts g gateways p proxies d diagnose
```

上から下まで読んでください:

1. **各行はアプリです** — クロード コード、コーデックス、ZCode、DeepSeek ハーネス (`dsh`)、コマンド コード (`commandcode`)、Pi (`pi`)、または Omp (`omp`)。ジェミニ、キロ、ワークバディはここには*いません*。アカウントで自分のログインを切り替えるだけです。
2. **中央の列**は、誰が電力を供給しているか (アカウント、ゲートウェイなど)、および AnyPick が設定したモデルを示します。
3. **右側のステータス**は平易な英語です: 準備完了、ネイティブ、未設定、または注意。
4. **破線ルールの下の 2 行** は、押す前*に <kbd>enter</kbd> が何をするかを常に示します。
5. **フッター**は、この画面の完全なキーマップです。キーがリストされていない場合、ここでは何も行われません。

### 各ステータスの意味

|わかりますか |意味 |何をすべきか |
| --- | --- | --- |
| **準備完了** | AnyPick はすでにこのアプリをルーティングしています |別のソースまたはモデルが必要な場合は、<kbd>enter</kbd> |
| **ネイティブ** |アプリ自体のログインは機能しますが、AnyPick はまだルートを管理していません。オプション — AnyPick に引き継いでもらいたい場合のみ、<kbd>enter</kbd> を押してください。
| **設定されていません** |まだルートがありません | <kbd>enter</kbd> → **アプリに接続** |
| **注意** |何かを修正する必要があります (キーが見つからない、チェックに失敗したなど) | <kbd>enter</kbd> または <kbd>d</kbd> を診断 |

## ルートを構築する（メインフロー）

構成ファイルを手動で編集することはありません。アプリで <kbd>enter</kbd> を押し、短い画面を 4 回歩きます。 **最終確認まで何も書き込まれません。**

### 1. ホーム — アプリを選択します

<kbd>↑</kbd> <kbd>↓</kbd> (または <kbd>j</kbd> <kbd>k</kbd>) で移動します。アプリ — クロード コード、コーデックス、ZCode、`dsh`、`commandcode`、`pi`、または `omp` をハイライトします。 <kbd>enter</kbd>を押します。

- 行が空またはネイティブのみの場合、フッターには **アプリに接続** と表示されます。
- すでに準備ができている場合、フッターには **ルート変更** と表示されます。

### 2. ソース — 誰が電力を供給するべきですか?

```
 anypick / apps / Claude / source

  Native accounts
 › Anthropic · work@example.com        current live login
   Anthropic · personal

  Gateways & proxies
   openrouter-work                     gateway · default model set
   grok/work                           account proxy

  Saved setups
   @work-stack                         preset
 ──────────────────────────────────────────
 Route Claude through grok/work
 account proxy · model routing is configured next
 enter choose route a accounts g gateways esc back
```

3 つのグループを平易な言葉で説明すると、次のようになります。

|グループ |こんなときはこれを選んでください… |
| --- | --- |
| **ネイティブ アカウント** | Claude、Codex、または Z.ai を *独自の* プロバイダー ログインに使用したいとします。 AnyPick は保存された資格情報を切り替えます。アプリは独自のモデル ピッカーを保持します。 ZCode アカウントは、暗号化されたローカル ログインから検出することも、Z.ai のブラウザ フローを通じて追加することもできます。 |
| **ゲートウェイとプロキシ** |別のプロバイダー、API キー エンドポイント、マルチアカウント プール、またはプロキシ ハブが必要です。次に AnyPick がモデルを設定します。 |
| **保存された設定** |プリセット (`@name`) はすでに`presets` テーブルにあります。まだ作成するコマンドがないため、新規インストールではこのグループは空です。 |

**安全なペアリング**のみが表示されます。 「クロード → ランダムな互換性のないもの」は表示されません。空のリストは、最初にアカウントを保存する (<kbd>a</kbd>) か、ゲートウェイ (<kbd>g</kbd>) を追加することを意味します。

ネイティブ行 → 結果は **Switch …**;他の行 → **…を介してルーティング**。

### 3. モデル — 必要な場合のみ

ネイティブの同じプロバイダー スイッチの場合はスキップされます。

それ以外の場合:

```
 anypick / apps / Claude / models

 › default     grok-code-fast-1
   sonnet      (same as default)
   opus        (same as default)
   haiku       (same as default)
 ──────────────────────────────────────────
 …
 enter edit model · a preview route
```

- **Codex** — 1 つのデフォルト モデル。
- **Claude** — デフォルトとオプションのソネット / 作品 / 俳句の役割 (これらの名前を呼び出すツールの場合)。

<kbd>enter</kbd> で行を編集し、候補を入力または選択して、<kbd>a</kbd> (または表示されている確認キー) を押してプレビューを開きます。

### 4. プレビュー — 読んでからアクティブ化する

```
 anypick / apps / Claude / preview

 Activate this route for Claude?

 · bind Claude → grok/work
 · set model grok-code-fast-1
 · start local proxy if needed
 · write client config

 enter activate route   esc back
```

これは、CLI が実行するプランと同じです。後でステップが失敗した場合、AnyPick はすでに変更された内容をロールバックします。 <kbd>enter</kbd> を押して適用し、<kbd>esc</kbd> を押して戻ってソースまたはモデルを変更します。

アクティベーションが正常に完了すると、**●準備完了**でアプリに戻り、その行に新しいソース · モデルが表示されます。

## 具体的な例

目標: **クロード コードは Grok 作業ログインを使用する必要があります。**

1. Grok のツールで一度ログインします (AnyPick がサインインすることはありません)。
2.  AnyPick で: <kbd>a</kbd> → アカウント → そのログインを `work` (または `anypick add account grok --current --name work`) として保存します。
3. アプリに戻り、**クロード**、<kbd>enter</kbd>をハイライトします。
4.  [**ゲートウェイとプロキシ**] で、**grok/work** を選択します。
5. 求められたら、デフォルトのモデルを設定します。
6. プレビューを読む→ <kbd>enter</kbd>。

クロードは敗走しました。いつものようにクロード コードを開きます。 AnyPick は必要なものをすでに書いています。 Codex、OpenRouter などのゲートウェイ、プール、またはプリセットでも同じパスが機能します。

## アプリのキー

|キー |アクション |
| --- | --- |
| <kbd>enter</kbd> |ルートの接続または変更 (ソース → モデル → プレビュー) |
| <kbd>a</kbd> / <kbd>tab</kbd> |アカウント |
| <kbd>g</kbd> |ゲートウェイ |
| <kbd>p</kbd> |プロキシ |
| <kbd>d</kbd> |診断 |
| <kbd>h</kbd> / <kbd>?</kbd> |この画面のヘルプ |
| <kbd>q</kbd> |ターミナル UI を閉じます (既存の互換性プロセスは変更されません)。

## その他のボード (脇役)

<kbd>tab</kbd> は **アプリ → アカウント → ゲートウェイ → プロキシ → アプリ** をサイクルします。セカンダリ ボードの <kbd>esc</kbd> はアプリに戻ります。

|ボード |それを使用して… |
| --- | --- |
| **アカウント** |ログインの保存、切り替え、更新、インポート/エクスポート、削除 |
| **ゲートウェイ** |エンドポイント + API キー プロファイルを保存します。プロキシのようにアプリにバインドする |
| **プロキシ** |ローカル トランスレータ、プール、プロキシ ハブの開始/停止 |

これらのボードは、「クロードが何を使用しているか?」というアプリを置き換えることはありません。 — Apps が選んだ棚に在庫を置いています。

### アカウントキー

|キー |アクション |
| --- | --- |
| <kbd>enter</kbd> |現在のログインを切り替える、アクティブに表示する、または保存する |
| <kbd>v</kbd> |詳細と使い方 |
| <kbd>a</kbd> |ログインを追加する |
| <kbd>i</kbd> / <kbd>e</kbd> |インポート/エクスポート |
| <kbd>r</kbd> |リフレッシュ |
| <kbd>s</kbd> |変更されたライブ ログインをスナップショット上に保存する |
| <kbd>d</kbd> |削除 |
| <kbd>f</kbd> |プロバイダーでフィルターする |

<kbd>i</kbd> を押すと、インポート プロンプトに `.json` エンベロープと、現在のフォルダーと `~/.anypick/exports/` からの AnyPick バックアップ ファイルがリストされます。 <kbd>↑</kbd>/<kbd>↓</kbd> を使用していずれかを選択するか、<kbd>tab</kbd> を使用して完了します。プロバイダーのアカウント リストからプロンプトが開かれると、マルチアカウント バックアップはそのプロバイダーのアカウントのみをインポートします。

### ゲートウェイキー

|キー |アクション |
| --- | --- |
| <kbd>enter</kbd> |このゲートウェイを使用するアプリを管理する |
| <kbd>m</kbd> |デフォルトのモデルを編集する |
| <kbd>e</kbd> |エンドポイントの編集 |
| <kbd>a</kbd> / <kbd>d</kbd> |追加/削除 |
| <kbd>f</kbd> |プロバイダーでフィルターする |

### プロキシキー

|キー |アクション |
| --- | --- |
| <kbd>enter</kbd> |アプリの起動、管理、または未保存のログインの保存 |
| <kbd>m</kbd> |アプリを管理してからモデルを編集する |
| <kbd>s</kbd> / <kbd>r</kbd> |停止/再起動 |
| <kbd>d</kbd> |自動起動を無効にする |
| <kbd>l</kbd> |ログ |
| <kbd>p</kbd> |マルチアカウントプールのオン/オフ |
| <kbd>space</kbd> |プールメンバーを一時停止または有効にする |
| <kbd>f</kbd> |プール上のフェイルオーバー ガード |

## ステータスグリフ

|グリフ |アプリについて |他の場所 |
| --- | --- | --- |
| `●` |準備完了 |ライブ / 使用中 |
| `○` |設定されていない/停止しています |保存/停止 |
| `◐` |注意 |変更されました (ライブログイン≠スナップショット) |
| `×` |失敗しました |失敗/利用不可 |

`NO_COLOR=1` では、形は依然として意味を持ちます。プレーン端子は、`*`、`o`、`!`、`x` にフォールバックします。

## UIを閉じる

- <kbd>q</kbd> — 端末 UI を離れます。既存の互換性プロセスは変更されません。

これらのショートカットは、Xcode から起動された `AnyPick.app` を所有したり終了したりしません。ネイティブ アプリはバンドルされた Go ヘルパーを所有しており、通常のアプリの起動、ウィンドウ、終了動作によって制御されます。 [macOS アプリとメニュー バー](/ja/docs/guides/tray) を参照してください。

同じルート構築がスクリプトのコマンド (`anypick use claude --with grok/work`) として存在します。 UI は弱いモードではありません。インストールと最初の保存については [はじめに](/ja/docs/getting-started) を、プールとハブについては [プロキシ](/ja/docs/guides/proxies) を参照してください。
