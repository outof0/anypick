Tên lệnh là `anypick`. Tải xuống kho lưu trữ được liệt kê tổng kiểm tra từ Bản phát hành GitHub hoặc cài đặt trình khởi chạy npm mỏng với `npm install --global anypick` (Nút 18+; tải xuống CLI gốc phù hợp trong lần chạy đầu tiên). Trong quá trình phát triển, hãy chạy cùng một cây lệnh từ quá trình kiểm tra với `make run ARGS="…"`; ví dụ: `make run ARGS="list accounts"`.

Ứng dụng macOS gốc là một mục tiêu thuộc sở hữu của ứng dụng riêng biệt. Nó tự khởi chạy dịch vụ Go đi kèm của mình và không cần CLI này để quản lý nó.

## Cờ toàn cầu

Hợp lệ trên mọi lệnh.

| Cờ | Hiệu ứng |
| --- | --- |
| `-V, --version` | In phiên bản và thoát |
| `--json` | Đầu ra máy có thể đọc được |
| `-v, --verbose` | Ghi nhật ký dài dòng |
| `-q, --quiet` | Sản lượng tối thiểu |
| `--dry-run` | In kế hoạch; không viết gì |
| `--reveal` | Hiển thị bí mật - nguy hiểm |
| `--no-input` | Không bao giờ nhắc, ngay cả trên TTY |
| `-y, --yes` | Bỏ qua xác nhận phá hoại |
| `--trace` | In tên bước nội bộ, không có bí mật |
| `--tui` | Mở giao diện người dùng Terminal cho lần chạy này |
| `--tray` | Chọn bề mặt khay tương thích cho nguồn này chạy CLI |

## binding

```bash
anypick use <client> --with <source> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick use codex --with <source> --profile <name> [--model <id>] [--transport auto|direct|proxy] [--allow-foreign-config]
anypick run <client> (--with <source>|--profile <name>) [--model <id>] -- <args…>
anypick codex profile login <name> [--auth-method <id>] [--source <id>]
anypick codex profile list
anypick codex profile show <name>
anypick codex profile remove <name> [--yes]
anypick current <provider>
anypick models <client> [--with <source>]
anypick link <client> [--with <source>] [--model <id>] [--allow-foreign-config]
anypick unlink [client]
anypick reset [client]
```

| Lệnh | Mô tả |
| --- | --- |
| `use` | Đặt những gì client sử dụng theo mặc định (bắt buộc phải có `--with`) |
| `run` | Ra mắt một client với sự binding hiệu quả của nó |
| `current` | Hiển thị các binding hiệu quả của một nhà cung cấp |
| `models` | Liệt kê các id mô hình mà nguồn bị binding xuất bản |
| `link` / `unlink` | Các binding trong phạm vi dự án cho thư mục hiện tại; `link` không có `--with` áp dụng lại thông số chung được lưu trữ |
| `reset` | Xóa cấu hình do AnyPick quản lý cho client |

`--with` chấp nhận tài khoản (`grok/work`), tên cổng, nhóm (`pool:gemini`), Proxy Hub (`hub:default`) hoặc preset (`@work-stack`). `--transport` ghim chính sách tuyến đường thay vì để người lập kế hoạch chọn.

#### Cấu hình client AnyPick không sở hữu

AnyPick ghi các tệp cấu hình của các công cụ khác, vì vậy nó từ chối thay thế một giá trị mà nó không thể chứng minh là nó đã ghi. Nếu `~/.claude/settings.json` hoặc một cấu hình Codex đã trỏ đến thông tin đăng nhập hoặc điểm cuối của riêng bạn, thì `use` không thành công với `CLIENT_CONFIG_FOREIGN` và đặt tên cho tệp cũng như các khóa bị đe dọa — cấu hình này được giữ nguyên theo byte.

`--allow-foreign-config` là câu trả lời rõ ràng: nó sao lưu tệp hiện tại dưới `$ANYPICK_HOME/recovery/clients/<client>/` rồi thay thế các giá trị đó. Sự đồng ý được thực hiện cho mỗi lần chạy và không bao giờ tồn tại, đồng thời ứng dụng dành cho máy tính để bàn sẽ đặt câu hỏi tương tự bằng nút **Quản lý bằng AnyPick** thay vì gắn cờ. Ứng dụng khách AnyPick đã quản lý (điểm cuối proxy loopback hoặc cấu hình mang điểm đánh dấu được quản lý của AnyPick) được cập nhật mà không cần yêu cầu.

### Hồ sơ Codex được đặt tên

`--profile` đặt cho Codex một tên hồ sơ gốc ổn định trong khi AnyPick lưu trữ nguồn đằng sau tên đó. Điều này hữu ích khi một shell hoặc tập lệnh cần một số tuyến đã lưu: mỗi cấu hình có `CODEX_HOME`, `<name>.config.toml` và `auth.json` riêng. Cấu hình được proxy hỗ trợ cũng nhận được tệp môi trường chỉ dành cho chủ sở hữu.

Đối với tài khoản Codex đã lưu, `auto` sử dụng trang chủ hồ sơ gốc và sao chép tài khoản đã lưu `auth.json`; nó không chạm vào ứng dụng trực tiếp trên máy tính để bàn `CODEX_HOME`. Để tạo tài khoản và hồ sơ mà không cần chuyển đổi thông tin đăng nhập trên máy tính để bàn, hãy sử dụng `profile login`:

```bash
anypick codex profile login work
anypick use codex --with codex/work --profile work --model gpt-5.6
anypick use codex --with openrouter-work --profile gateway
anypick use codex --with hub:default --profile hub-work
```

`profile login` chạy thông tin đăng nhập Codex chính thức bằng `CODEX_HOME=$ANYPICK_HOME/clients/codex/profiles/work/codex-home`, do đó luồng trình duyệt ghi tài khoản B vào đó. Sau đó, AnyPick sẽ lưu cùng một tệp dưới dạng ảnh chụp nhanh `codex/work` và khôi phục con trỏ hoạt động trên màn hình. Thay vào đó, để sử dụng proxy được tài khoản hỗ trợ, hãy bật proxy đó và ghim `--transport proxy`:

```bash
anypick proxy enable codex work
anypick use codex --with codex/work --profile work-proxy --transport proxy
```

Cấu hình Codex CLI mặc định chấp nhận các tuyến giống nhau mà không có `--profile`:

```bash
anypick use codex --with codex/work --transport proxy
anypick use codex --with hub:default
```

Để chạy một cấu hình thông qua quy trình Codex CLI bị cô lập, hãy sử dụng:

```bash
anypick run codex --profile personal -- exec --help
anypick codex profile list
```

Đối với lệnh gọi thô, hãy sử dụng lệnh `launch` được in bởi `anypick codex profile show <name>`. Nó đặt rõ ràng `CODEX_HOME` dành riêng cho hồ sơ; các cấu hình được proxy hỗ trợ cũng lấy nguồn tệp env chỉ dành cho chủ sở hữu của chúng. Không in hoặc cam kết tệp env đó: nó chứa thông tin xác thực proxy cục bộ. Các cấu hình được trung tâm hỗ trợ có mã thông báo tuyến đường riêng biệt, do đó, việc kích hoạt một cấu hình sẽ không làm mất hiệu lực tuyến đường mặc định hoặc cấu hình khác. Các lệnh này cấu hình Codex CLI; Codex Desktop giữ tài khoản đăng nhập của riêng mình và không tuân theo `CODEX_HOME` của CLI.

`anypick codex profile remove <name>` xóa tuyến đường và các tệp AnyPick đã tạo cho tuyến đường đó (cấu hình hồ sơ, danh mục mô hình và tệp env của nó). Thông tin riêng tư `CODEX_HOME` của hồ sơ vẫn được giữ nguyên nên việc đăng nhập lại với cùng tên sẽ sử dụng lại hồ sơ đó. Việc xóa *tài khoản* mà hồ sơ trỏ đến sẽ khác: `anypick account remove codex work` cũng xóa các hồ sơ được đặt tên liên kết với tài khoản đó, bao gồm cả nhà thông tin xác thực và đặt tên chúng trong kết quả. Các cấu hình trỏ đến cổng, Hub, nhóm hoặc tài khoản khác sẽ không được chạm vào. AnyPick quét các hồ sơ còn sót lại từ lần xóa trước đó ở lần khởi động tiếp theo và `anypick doctor` báo cáo chúng cho đến lúc đó.

<Aside type="caution" title="Sử dụng không tương tác">
`use <client>` yêu cầu `--with`. Không có nó thì không có gì để lấy nguồn từ đó, vì vậy lệnh sẽ thoát `2` thay vì đoán.
</Aside>

## Hàng tồn kho

```bash
anypick list [providers|accounts]   # default: providers
anypick providers
anypick clients
```

Không có bí danh `ls` và không có biểu mẫu `list gateways|clients|presets`: cổng, preset và plugin đều có nhóm lệnh riêng bên dưới.

## Thêm nguồn

```bash
anypick add account <provider> --name <name> [--current|--new] [--source <id>] [--force]
anypick add account <provider> --new --name <name> [--auth-method <id>] [--source <id>]
anypick add account <provider> --name <name> --credential <kind> --secret [--option profile=<id>] [--region <region>]
anypick add gateway <name> --provider <id> [--endpoint url]
    [--api-key [key] | --api-key-env <var> | --secret <key>]
    [--model <id>] [--models <role=id>]
```

`--current` chụp nhanh thông tin đăng nhập hiện đang hoạt động. `--new` sử dụng thông tin đăng nhập vào trình duyệt có sẵn do nhà cung cấp sở hữu và lưu thông tin xác thực gốc thu được; nếu không, nó sẽ lưu thông tin đăng nhập hiện tại và in phần tiếp theo thủ công. Các phương thức chính thức được ưu tiên, trong khi `--auth-method <id>` có thể chọn bất kỳ phương thức nào mà nhà cung cấp khai báo, bao gồm cả phương thức cộng đồng. `--source <id>` chọn một cửa hàng gốc rõ ràng cho nhà cung cấp nhiều nguồn. `--credential <kind>` (bao gồm `--api-key` dành cho các nhà cung cấp tương thích) cộng với `--secret`, `--api-key` hoặc lời nhắc `--api-key` trần cung cấp thông tin xác thực khóa API; `--profile` hoặc `--option profile=<id>` chọn cấu hình điểm cuối và `--region` là vùng đám mây khóa API Kiro. Bỏ qua giá trị `--secret` để ​​sử dụng lời nhắc ẩn hoặc chuyển giá trị đó qua `ANYPICK_SECRET`.

## Tài khoản

```bash
anypick account list [provider]
anypick account refresh [provider [name]] [--all]
anypick account remove <provider> <name> [--yes]
anypick account export <provider> <name> [--out <file>]   # -o <file>; defaults to ~/.anypick/exports/*.json
anypick account export [provider] --all [--out <file>] [--overwrite]
anypick account import <provider> <name> <file.json> [--force]   # or -i <file.json>
anypick account import <file.json> [<file2.json> …] [--force]
```

`refresh` áp dụng thông tin đăng nhập trực tiếp hiện tại của nhà cung cấp vào tài khoản đã lưu. Không có nhà cung cấp, nó sẽ thử mọi tài khoản đã lưu; với một nhà cung cấp (và tùy chọn tên), nó chỉ làm mới những nhà cung cấp đó. Việc làm mới sẽ cung cấp cho một tài khoản ảnh chụp nhanh của một tài khoản khác bị từ chối — một lần đăng nhập vẫn là một tài khoản — vì vậy việc làm mới toàn bộ nhà cung cấp không thể âm thầm thu gọn các thông tin đăng nhập khác nhau vào tài khoản trực tiếp hiện tại. Không có bí danh `rm`.

## Cổng

```bash
anypick gateway add <name> --provider <id> [--endpoint url]
    [--api-key [key]|--api-key-env <var>|--secret <key>]
    [--model <id>] [--models <role=id>]
anypick gateway list
anypick gateway show <name>
anypick gateway edit <name> [--endpoint url] [--model id] [-m id] [--api-key key]
anypick gateway remove <name>
```

`show` che giấu khóa API trừ khi bạn vượt qua `--reveal` toàn cầu. `edit` chấp nhận `--api-key` để ​​thay thế khóa được lưu trữ và `-m` là dạng rút gọn của `--model`.

## preset

```bash
anypick preset list
anypick preset show <name>
anypick preset remove <name>
```

Tên preset được viết mà không có `@` ở đây; tiền tố `@` chỉ là cách bạn tham chiếu tiền tố trong `--with`.

## Proxy

```bash
anypick proxy enable|disable <provider> <account> [--port N]
anypick proxy start|stop|status|token <provider> <account>
anypick proxy config <provider> <account> [--port N]
anypick proxy restart <provider> <account>
anypick proxy logs <provider> <account> [--lines N] [--follow]
```

`--port` trên `enable`/`config` ghim một cổng; nếu không cổng miễn phí đầu tiên sẽ được sử dụng. `token` in hoặc xoay (`--rotate`) mã thông báo xác thực / khóa API cho proxy. `logs` in 50 dòng cuối cùng theo mặc định.

### Bể bơi

```bash
anypick proxy pool status <provider>
anypick proxy pool enable <provider> [--strategy failover|round-robin]
    [--mode single|multi] [--port N] [-p N] [+account|-account ...]
anypick proxy pool member <provider> <account> <on|off>
anypick proxy pool start <provider>
anypick proxy pool stop <provider>
anypick proxy pool disable <provider>
```

`enable` thêm thành viên `+account` và tạm dừng `-account` thành viên trong một cuộc gọi; chiến lược mặc định là `failover`, chế độ mặc định `multi`. Với `round-robin`, mỗi yêu cầu sẽ bắt đầu ở thành viên đủ điều kiện tiếp theo; với `failover`, tài khoản trả lời cuối cùng sẽ tiếp tục phân phát cho đến khi bị từ chối. Dù bằng cách nào, lỗi trong hạn ngạch sẽ chuyển yêu cầu sang thành viên tiếp theo.

### Proxy Hub

```bash
anypick proxy hub status <name>
anypick proxy hub enable <name> [--host <host>] [--port N] [-p N]
    [--strategy failover|round-robin] [--start]
anypick proxy hub source <name> <provider> <account>
anypick proxy hub owner <name> <model> <provider>/<account>
anypick proxy hub preview <name>
anypick proxy hub start <name>
anypick proxy hub stop <name>
```

`source` chuyển đổi: các nguồn hiện tại bị xóa, những nguồn vắng mặt được thêm vào (bắt buộc phải có tên tài khoản). `--strategy round-robin` làm cho trung tâm trải rộng từng mô hình trên các tài khoản được kích hoạt có thể phân phát nó — tài khoản của nhà cung cấp mà mô hình phân giải — thay vì ghim nó vào một tài khoản; không có cờ, chế độ hiện tại được giữ nguyên. Liên kết với `--with hub:<name>` sau khi bật ít nhất một nguồn. `owner` chọn tài khoản nào thắng khi hai nguồn quảng cáo cùng một id mô hình; `preview` làm mới danh mục và in các tuyến đường cùng với xung đột.

## Plugin

```bash
anypick plugin list
anypick plugin add <dir>
anypick plugin enable <name>
anypick plugin disable <name>
anypick plugin trust <name>
anypick plugin remove <name>
```

`add` cài đặt một thư mục cục bộ **đã tắt**. `enable` là quyết định và lời nhắc tin cậy; nó cần `-y` toàn cầu khi không có TTY. `trust` ghim lại thông báo gói sau khi mã của plugin thay đổi. Xem [Plugin](/vi/docs/guides/plugins).

## Nguồn CLI bề mặt và người giám sát tương thích

```bash
anypick tui
anypick tray
anypick start
anypick status
anypick stop
```

`anypick tui` luôn mở [Ứng dụng / Giao diện người dùng thiết bị đầu cuối](/vi/docs/guides/terminal-ui). Họ lệnh `tray` được triển khai bởi công cụ Go (cây TypeScript và bề mặt khay của nó không còn tồn tại): `anypick tray` in ảnh chụp nhanh tương thích, trong khi điều khiển `start`, `status` và `stop` người giám sát tương thích và các proxy mà nó sở hữu.

Các lệnh này không xác định quyền sở hữu ứng dụng gốc. Ứng dụng macOS phân giải và khởi động `Contents/Helpers/anypick-core`, giữ bảng điều khiển nhanh trên thanh menu bên trong cùng một ứng dụng và dừng trình trợ giúp trên ứng dụng cụ thể Thoát. Xem [thanh menu và ứng dụng macOS](/vi/docs/guides/tray).

## Kiểm tra cập nhật

```bash
anypick update
anypick update --json
```

Kiểm tra tư vấn này so sánh phiên bản đang chạy với bản phát hành GitHub mới nhất. Nó in lộ trình cài đặt có sẵn; nó không thay đổi cài đặt. Hướng dẫn trỏ đến trang phát hành, trình quản lý gói có sẵn hoặc kiểm tra nguồn:

```bash
git pull && make build
```

Cho đến khi bản phát hành được xuất bản, quá trình kiểm tra sẽ báo cáo `no published release yet` và chỉ ra quy trình làm việc nguồn. `--json` trả về phiên bản hiện tại và mới nhất:

```bash
anypick update --json
```

```json
{ "current": "1.0.0", "latest": "1.1.0" }
```

Công cụ cập nhật cũng có các lệnh kiểm tra và tải xuống rõ ràng. Ngăn **Cài đặt → Cập nhật** của macOS sử dụng các lệnh tương tự:

```bash
anypick update check --json
anypick update download --json
```

`check` báo cáo trạng thái cập nhật và hành động cài đặt cho kênh được phát hiện. `download` tìm nạp nội dung cài đặt trực tiếp vào bộ đệm người dùng của AnyPick và kiểm tra SHA-256 của nó dựa trên tệp tổng kiểm tra từ bản phát hành đó. Nó không thay thế hoặc khởi động lại ứng dụng đã cài đặt. Trong Cài đặt, **Hiển thị trong Finder** mở tệp đã tải xuống để bạn có thể cài đặt tệp đó bằng các bước thông thường cho kênh đó. Cài đặt trình quản lý gói hiển thị lệnh nâng cấp tương ứng.

Ứng dụng macOS không được công chứng; Các bước phê duyệt lần đầu ra mắt có trong [Ứng dụng dành cho máy tính để bàn](/vi/docs/guides/tray).

<Aside type="caution" title="Tải xuống không tự cài đặt">
Đối với cài đặt trực tiếp, bản cập nhật sẽ kiểm tra lượt tải xuống và kiểm tra nội dung phát hành. Bạn vẫn cài đặt bản tải xuống đó theo cách thủ công. Sử dụng lệnh do AnyPick hiển thị để cài đặt được quản lý gói hoặc để cài đặt lại tệp `.deb` hoặc `.rpm` cục bộ.
</Aside>

## Hoàn thiện vỏ

```bash
anypick completion zsh     # also: bash | fish
```

Thêm nó vào tệp khởi động shell của bạn hoặc đánh giá nó trực tiếp:

```bash
source <(anypick completion zsh)
```

## Mã thoát

| Mã | Ý nghĩa |
| --- | --- |
| `0` | Thành công |
| `1` | Lỗi vận hành |
| `2` | Cách sử dụng không hợp lệ — thiếu ứng dụng khách hoặc nguồn, chỉ có `use` không có TTY |
| `3` | Không tìm thấy |
| `4` | Yêu cầu xác thực |
| `5` | Xung đột về khả năng, vận chuyển không được hỗ trợ hoặc không có binding |
| `6` | Suy giảm sức khỏe |
| `7` | Thiếu phần phụ thuộc bắt buộc, chẳng hạn như tệp nhị phân proxy bên ngoài |
| `8` | Phong bì nhập khẩu không đúng định dạng hoặc không đáng tin cậy |
| `9` | Nhập vượt quá giới hạn kích thước hoặc số lượng tệp |
| `130` | Đã hủy bằng SIGINT |

## Biến môi trường

### AnyPick

| Biến | Hiệu ứng |
| --- | --- |
| `ANYPICK_HOME` | Thư mục dữ liệu. Mặc định `~/.anypick` |
| `ANYPICK_LANG` | Ngôn ngữ hiển thị (`en`, `zh-CN`, `es`, `fr`, `de`, `ja`, `ko`, `pt-BR` hoặc `vi`). Mặc định là ngôn ngữ quy trình (`LC_ALL`, `LC_MESSAGES` hoặc `LANG`; Windows sử dụng ngôn ngữ giao diện người dùng ưa thích); các ngôn ngữ không được hỗ trợ và các Messages chưa được dịch sẽ quay trở lại tiếng Anh |
| `ANYPICK_SECRET` | Giá trị thông tin xác thực cho `add account` / `add <provider>`, vì vậy nó không hiển thị trong danh sách quy trình |
| `ANYPICK_NO_PLUGINS=1` | Bỏ qua hoàn toàn việc tải plugin |
| `NO_COLOR` | Thả tất cả màu sắc; glyphs vẫn mang trạng thái |

### Ghi đè nhà cung cấp

| Biến | Hiệu ứng |
| --- | --- |
| `GEMINI_API_KEY`, `GOOGLE_API_KEY` | Khóa API Gemini trực tiếp được đọc bởi `add account gemini --current` |
| `GEMINI_API_KEY_UPSTREAM` | Ghi đè URL cơ sở upstream của khóa API Gemini |
| `GEMINI_CODE_ASSIST_UPSTREAM` | Ghi đè điểm cuối Code Assist Gemini |
| `GEMINI_CLI_HOME`, `GEMINI_CONFIG_DIR` | Độ phân giải cấu hình Gemini (`GEMINI_CLI_HOME` thắng, phù hợp với CLI) |
| `CLAUDE_BINARY`, `CODEX_BINARY`, `KIRO_BINARY`, `GROK_BINARY` | Khởi chạy một tệp nhị phân của client cụ thể |
| `KIROLINK_BIN` | Đường dẫn đến tệp nhị phân `kirolink` bên ngoài |
| `WORKBUDDY_BASE_URL` | Ghi đè cơ sở API WorkBuddy/CodeBuddy |
| `CLINE_API_BASE_URL`, `CLINE_WORKOS_CLIENT_ID` | Ghi đè Cline API/WorkOS (id client là công khai; nó ghi đè mặc định tích hợp sẵn) |
