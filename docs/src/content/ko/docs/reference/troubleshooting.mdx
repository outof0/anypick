## 먼저 `anypick doctor`를 실행하세요

```bash
anypick doctor
anypick doctor --fix --dry-run
anypick doctor --fix -y
```

`doctor`는 전체 설치를 검사합니다. 하나의 클라이언트나 공급자로 범위를 좁히지 않습니다. AnyPick 데이터 디렉터리, SQLite 데이터베이스, 저장된 계정 및 게이트웨이, 파일 권한, PID 레코드, 실행 중인 프록시, 완료되지 않은 모든 작업 저널 항목을 확인합니다.

## `--fix`가 만질 수 있는 것

`--fix`는 6가지 작업으로 구성된 하드 허용 목록에서 작동합니다. 다음을 수행할 수 있습니다.

-  오래된 PID 파일 삭제
- 고아 프록시 중지
- `run`가 남긴 임시 클라이언트 오버레이 삭제
- AnyPick 소유 경로에 대한 수리 권한
- 파생 캐시 재구축
- 중단된 저널 롤백 완료

계정을 전환하거나, 패키지를 설치하거나, 기본 인증 파일을 터치하거나, 바인딩을 변경하지 않습니다. 허용 목록 외부의 모든 항목은 **수동 전용**으로 보고되며 그 옆에 제안 사항이 인쇄됩니다. 터미널 UI에는 동일한 분할이 표시됩니다.

임시 오버레이 작업은 주의 깊게 읽어야 할 작업입니다. 오버레이는 시스템 임시 디렉토리 아래의 디렉토리이며 어떤 프로세스가 이를 소유하고 있는지 기록하지 않으므로 `--fix`는 연령만 기준으로 판단하고 지난 한 시간 동안 수정된 내용을 거부합니다. 긴 `anypick run` 세션은 해당 시간보다 오래 지속될 수 있으며 수리로 인해 실행 중인 클라이언트의 격리된 홈이 삭제됩니다. 오랫동안 실행되는 `run`가 열려 있는 경우 이 작업을 건너뛰고 해당 세션이 끝나면 직접 디렉터리를 삭제하세요. 목록에 있는 다른 모든 행동은 대상을 건드리기 전에 대상이 죽었다는 것을 증명합니다.

오래된 잠금 파일은 의도적으로 목록에 **아닙니다**. AnyPick의 잠금은 보유 프로세스가 종료될 때 커널이 해제하는 `flock(2)` 설명자이므로 충돌로 인해 삭제할 수 있는 오래된 항목이 남지 않습니다. 그리고 라이브 프로세스가 여전히 보유하고 있는 잠금 파일을 제거하는 "복구"는 동시 계정 변경 사항이 서로 손상되는 것을 방지하는 코디네이터를 무력화시킵니다(ADR 0009). 이 페이지의 초기 초안에서는 해당 조치를 약속했습니다. 그것은 존재할 수 없습니다.

<Aside type="tip" title="먼저 미리보기">
`anypick doctor --fix --dry-run`는 허용 목록에 있는 작업이 실행될 정확한 내용을 인쇄합니다. 허용 목록이 추상적이지 않도록 한 번 수행해 볼 가치가 있습니다.
</Aside>

## 종료 코드 읽기

| 코드 | 의미 | 일반적인 원인 |
| --- | --- | --- |
| `1` | 운영 실패 | 명령 중 예기치 않은 런타임 오류 발생 |
| `2` | 잘못된 사용법 | `use` `--with` 또는 `--current`가 없거나 잘못된 플래그 |
| `3` | 찾을 수 없음 | 계정, 게이트웨이, 사전 설정 또는 클라이언트 이름이 존재하지 않습니다 |
| `4` | 인증이 필요합니다 | 로그인 또는 API 키가 누락되었거나 만료되었습니다. |
| `5` | 능력 충돌 | 소스가 해당 클라이언트를 제공할 수 없거나 바인딩이 존재하지 않습니다 |
| `6` | 건강 실패 | 상태 확인 실패 |
| `7` | 종속성 누락 | `kirolink`와 같은 외부 프록시 바이너리가 설치되지 않았습니다 |
| `8` / `9` | 수입이 거부되었습니다 | 내보내기 봉투가 잘못되었거나 아카이브가 너무 큽니다 |
| `130` | 취소됨 | Ctrl-C |

## 일반적인 상황

### 클라이언트가 실행되지만 소스를 무시합니다.

실제로 무엇이 적용되는지 확인하세요. 현재 디렉터리의 프로젝트 바인딩이 전역 기본값보다 뛰어납니다.

```bash
anypick current claude
```

오래된 프로젝트 바인딩이 성공하면 `anypick unlink claude`가 이를 제거합니다.

### `run` 바인딩 없이 5번 종료

해당 클라이언트에 대한 임시, 프로젝트 또는 전역 바인딩이 없습니다. 하나를 설정하십시오:

```bash
anypick use claude --with grok/work
```

### 프록시가 시작되지 않습니다

로그를 확인한 다음 포트를 확인하세요.

```bash
anypick proxy status gemini work
anypick proxy logs gemini work --lines 100
anypick proxy config gemini work --port 4131     # move it
```

이미 보유하고 있는 구성된 포트는 더 이상 시작에 실패하지 않습니다. AnyPick은 프록시를 사용 가능한 포트로 이동하고 유지하며 바인딩된 클라이언트를 다시 작성하고 이동을 경고로 보고합니다. 이전 세션에서 남은 프록시는 이름을 `anypick proxy stop gemini work`로 지정하여 중지할 수 있습니다. "모든 것을 중지"하는 형식은 없습니다. 인수가 없는 `anypick proxy` 명령은 사용법을 인쇄합니다.

### Gemini 프록시가 모델을 거부합니다.

OAuth 전용 Gemini 계정은 클라이언트에 로그인할 수 있지만 저장된 로그인의 `.env`에 `GEMINI_API_KEY`가 필요한 프록시를 구동할 수는 없습니다. 두 로그인이 모두 존재하는 경우 프록시가 제공해야 하는 소스를 저장하세요.

```bash
anypick add account gemini --current --source gemini-cli --name work
anypick add account gemini --current --source antigravity --name work
```

### 저장된 로그인과 실시간 로그인이 일치하지 않습니다.

터미널 UI는 이를 `◐ changed`로 표시합니다. 이는 AnyPick이 스냅샷을 찍은 후 공급자의 CLI가 새 자격 증명을 작성했음을 의미합니다. 새로운 것을 채택하십시오:

```bash
anypick account refresh codex
```

### 저장된 두 계정이 하나의 스냅샷을 공유합니다.

`anypick doctor`는 동일한 공급자의 두 이름이 동일한 자격 증명 스냅샷을 보유하는 경우 `duplicate-snapshot`를 보고합니다. 이들 사이를 전환해도 로그인은 변경될 수 없습니다. AnyPick은 새로운 쌍 생성을 거부하고 이전에 저장된 쌍만 정리하도록 요청합니다.

```bash
anypick doctor --json                          # exact names, and which to keep
anypick account remove workbuddy/work
```

`anypick doctor`는 유지할 계정을 `keep <provider>/<account>`로 표시하고 제거 명령을 출력합니다. 두 이름이 모두 활성 상태(하나는 활성이고 다른 하나도 클라이언트 바인딩에서 참조됨)라면 제거 명령 대신 클라이언트를 하나의 계정에 다시 바인딩하라고 안내해 정리 작업이 경로를 끊지 않도록 합니다.

### UI를 닫은 후에도 프록시가 계속 실행됩니다.

기본 앱의 기본 창을 닫아도 앱이 종료되지는 않습니다. 앱이나 메뉴 표시줄 빠른 패널에서 **Quit AnyPick**을 사용하여 번들 Go 서비스를 정상적으로 중지하세요.

소스 TUI를 닫으면 기존 호환성 프로세스도 변경되지 않습니다. 이 체크아웃에서 해당 호환성 감독자를 중지하려면 다음을 수행하세요.

```bash
make run ARGS="tray stop"
```

`make run ARGS="proxy stop"`는 계정 프록시 실행을 직접 중지합니다. TUI는 명시적으로 <kbd>Shift+D</kbd>를 누르거나 트레이 런타임 화면에서 시작할 때만 호환성 감독자를 시작합니다. 별도로 실행되는 `AnyPick.app`를 제어하지 않습니다.

### 활성화가 도중에 실패했습니다.

돌연변이 활성화 단계는 백업 경로와 함께 작업 저널에 기록되므로 활성화에 실패하면 이전 상태(클라이언트 구성, 기본 인증 및 시작된 프록시)가 복원됩니다. 롤백이 완료되기 전에 프로세스가 종료된 경우 `anypick doctor --fix`가 롤백을 완료합니다.

계정 전환은 동일한 트랜잭션입니다. 새로 선택한 계정을 바인딩된 클라이언트에 적용할 수 없는 경우 활성 포인터, 클라이언트 바인딩 및 이전 계정의 프록시가 모두 복원되고 오류가 이렇게 표시됩니다. 클라이언트가 여전히 이전 프록시를 가리키는 동안에는 앱이 새로운 활성 계정을 요청하는 것을 볼 수 없습니다.

## 더 깊이 파고들기

```bash
anypick --trace use claude --with grok/work    # name each step, no secrets
anypick proxy status <provider> <account>      # live listener state
anypick doctor --json                          # machine-readable findings
```

`--trace`는 활성화 계획을 단계별로 인쇄합니다. 이는 일반적으로 어느 단계가 실패했는지 확인하는 데 충분합니다. 계획을 실행하지 않고 보려면 `--dry-run`와 결합하세요.
