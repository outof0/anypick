게이트웨이는 엔드포인트, 자격 증명, 선택적으로 모델 목록 등 API 프로필입니다. 로그인 흐름이나 로컬 프로세스가 없습니다. 클라이언트가 원격 엔드포인트와 직접 통신합니다.

## 하나 추가

```bash
anypick add gateway openrouter-work \
  --provider openrouter \
  --endpoint https://openrouter.ai/api/v1 \
  --api-key "$OPENROUTER_API_KEY" \
  --model anthropic/claude-sonnet-4 \
  --models default=anthropic/claude-sonnet-4 \
  --models opus=anthropic/claude-opus-4-8

anypick use claude --with openrouter-work
anypick run claude
```

| 플래그 | 의미 |
| --- | --- |
| `--provider <id>` | 끝점이 따르는 카탈로그 모양 |
| `--endpoint <url>` | 기본 URL |
| `--api-key <key>` | AnyPick 데이터베이스에 저장된 키 |
| `--api-key-env <var>` | 키를 저장하는 대신 활성화 시 환경 변수에서 키 읽기 |
| `--model <id>` | 이 게이트웨이의 기본 모델 |
| `--models <role=id>` | 하나의 클라이언트 모델 역할(`default`, `sonnet`, `opus`, `haiku`, …)을 게이트웨이 모델에 고정합니다. 더 많은 역할을 위해 플래그를 반복하세요 |
| `--gateway-id <id>` | 엔드포인트당 여러 게이트웨이를 처리하는 공급자의 게이트웨이 ID |

`--models`는 무료 ID 목록이 아닌 역할 맵입니다. 저장된 값은 각 클라이언트의 자체 역할 슬롯에 기록되므로 기본 ID에는 연결할 역할이 없으며 플래그가 거부됩니다. 역할당 한 번씩 `role=model-id`를 전달합니다.

카탈로그 제공자에는 `anthropic`, `openai`, `openrouter`, `grok-api`, `gemini-api`, `litellm`, `local`, `custom` 및 `cloudflare-aigateway` — 전체 세트는 `src/go/internal/catalog/catalog.go`의 `Builtin()`입니다.

Cloudflare AI Gateway에는 명시적인 엔드포인트(기본 URL에 Cloudflare 계정 ID가 포함되어 있음)와 게이트웨이 ID가 필요합니다.

```bash
anypick add gateway cf-prod \
  --provider cloudflare-aigateway \
  --endpoint https://api.cloudflare.com/client/v4/accounts/ACCOUNT_ID/ai/v1 \
  --api-key "$CF_API_TOKEN" \
  --gateway-id my-gateway
```

공급자 기본값(`default`)을 사용하려면 `--gateway-id`를 생략하세요.

<Aside type="tip" title="저장하고 싶지 않은 키">
`--api-key-env OPENROUTER_API_KEY`는 비밀이 아닌 변수 이름을 기록합니다. AnyPick은 바인딩을 활성화할 때 이를 읽으므로 키는 환경이나 비밀 관리자에 유지됩니다.
</Aside>

## 게이트웨이 또는 프록시?

둘 다 소스이고 둘 다 같은 방식으로 끝납니다 — `use <client> --with <source>`. 그들은 뒤에 서있는 것이 다릅니다.

| | 프록시(계정) | 게이트웨이(API 프로필) |
| --- | --- | --- |
| 인증 | 기본 로그인 스냅샷과 로컬 프로세스 | AnyPick이 보유한 엔드포인트 + 키 |
| 설정 | 공급자 CLI로 로그인한 후 스냅샷 | 엔드포인트와 키 붙여넣기 |
| 모델 | 실행 중인 프록시에서 검색됨 | 게이트웨이 기본값 또는 바인딩별 |
| 요청은 어디로 가는가 | `127.0.0.1:<port>` → 업스트림 | 끝점까지 곧장 |

열쇠를 쥐고 있으면 게이트웨이에 접근하세요. 구독을 보유하고 있으면 계정을 찾으세요.

## 클라이언트 선택 도구의 모델

기본 모델 레지스트리(Codex, OpenCode, ZCode, Command Code 및 DSH)가 있는 클라이언트의 경우 AnyPick은 클라이언트에서 사용 가능한 ID가 선택한 게이트웨이 또는 프록시와 일치하도록 소스 범위 카탈로그를 작성합니다. `--model`로 기본값을 설정하세요. 클라이언트가 시작하는 모델이 됩니다.

Claude Code, Gemini CLI 및 Kiro는 쓰기 가능한 모델 레지스트리가 아닌 환경 변수 또는 기본 역할 슬롯을 통해 모델 선택을 노출합니다. AnyPick은 기본 기본값/역할 값을 구성하지만 해당 프로그램이 읽지 않는 클라이언트 측 목록을 만들 수는 없습니다.

계정 프록시에는 이것이 필요하지 않습니다. AnyPick은 클라이언트를 활성화할 때마다 실시간 `/v1/models` 카탈로그를 읽습니다.

## 게이트웨이 관리

```bash
anypick gateway list
anypick gateway show openrouter-work
anypick gateway edit openrouter-work -m anthropic/claude-sonnet-4
anypick gateway edit openrouter-work --endpoint https://…  --api-key "$NEW_KEY"
anypick gateway remove old-gateway -y
```

`show`는 키를 마스크합니다. 전역 `--reveal` 플래그를 전달하여 인쇄하는데 이는 말 그대로 위험합니다.

바인딩은 스냅샷이므로 게이트웨이를 편집해도 이미 바인딩된 클라이언트는 소급하여 변경되지 않습니다. `use`를 다시 실행하여 새 엔드포인트나 모델을 선택하세요.
