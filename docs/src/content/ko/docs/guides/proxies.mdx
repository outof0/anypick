클라이언트와 계정이 동일한 프로토콜을 사용하지 않는 경우 AnyPick은 둘 사이에 로컬 프록시를 실행합니다. 활성화의 일부로 요청 시 시작되고 감독자와 함께 중지되므로 일반적인 사용에서는 관리할 것이 없습니다. 이 페이지의 모든 내용은 검사 및 디버깅을 위한 것입니다.

## 프록시가 하는 일

각 공급자 프록시는 둘 이상의 유선 형식을 허용하고 공급자의 실제 API로 전달합니다.

- **grok** — OpenAI 호환 및 Anthropic 호환 경로, 인증된 업스트림 `/v1/models` 카탈로그 및 요청 모델 ID를 변경 없이 전달합니다.
- **opencode** — 모델이 지원하는 내용에 따라 메시지, 채팅 완료, 응답 및 Google 프로토콜 중에서 선택하는 Zen 및 Go 카탈로그
- **gemini** — 최신 `/v1/responses` 요청 및 SSE 수명주기 현재 Codex CLI 릴리스를 포함하여 키별 Gemini API 또는 OAuth별 코드 지원
- **kiro** — 외부 `kirolink` / `kiro-proxy` 바이너리가 설치된 경우 위임됨
- **workbuddy** — CodeBuddy 구독에 대한 OpenAI 채팅 완료(및 인류학적 번역). 일부 추론 모델은 횡설수설할 수 있습니다(`OK.` / `Let me
  write.`). 그런 일이 발생하면 회전을 멈추고 `hy3`와 같은 라우터가 아닌 슬러그를 선택하세요.
- **cline** — Cline 게이트웨이에 대한 OpenAI 채팅 완료
- **호환 제공자 플러그인** — 공급업체가 공개하는 경우 기본 Anthropic 메시지, 그렇지 않은 경우 OpenAI Chat Completions 및 Codex에서 사용하는 응답 수명 주기; API와 코딩 구독 키는 동일한 로컬 경계를 사용합니다.

모델 검색은 라이브 업스트림을 선호하며 `/models`가 없거나 사용할 수 없는 경우에만 공급자 소유 폴백을 사용합니다. Gemini는 API 키 계정의 경우 `models.list`를 읽고 OAuth 계정의 경우 Code Assist `fetchAvailableModels`를 읽습니다. OpenCode는 공급자 메타데이터와 라이브 카탈로그를 교차합니다. AnyPick 출시 없이 새 모델이 등장합니다.

추론 의도는 번역 후에도 살아남습니다. Codex 및 OpenAI `reasoning_effort`, 응답 `reasoning.effort`, Claude `output_config.effort`, 적응적 사고, 명시적 `budget_tokens` 및 가시적 사고 요약이 모두 보존됩니다. Google 경로는 동일한 의도를 Gemini의 `thinkingConfig`에 매핑하고 생각 요약을 최종 답변과 별도로 유지합니다. Native Anthropic 및 OpenAI 경로는 통과 경로입니다.

## 기본 포트

프록시는 풀 포트가 설정되어 있으면 해당 포트를 사용합니다. 그렇지 않으면 공급자가 `DefaultProxyPort`를 선언했을 때 그 포트를 사용하고, 그마저 없으면 공용 기본값인 `8080`을 사용합니다 (`src/go/internal/activation/planner.go`의 `plannedPoolPort`, `src/go/internal/proxy/service_pool.go`의 `defaultPoolPort`). 현재 선언된 기본 포트는 Ark `4155`, TokenHub `4156`, GroqCloud `4148`, Fireworks `4151`, Cerebras `4152`, NVIDIA NIM `4154`입니다 (`src/go/internal/provider/compatible.go`). 포트가 설정되지 않았고 공급자 기본값도 없으면 프록시가 사용 가능한 첫 포트를 선택합니다.

## 수동 수명주기

```bash
anypick proxy status <provider> <account>
anypick proxy start <provider> <account>
anypick proxy stop <provider> <account>
anypick proxy enable <provider> <account> [--port N]
anypick proxy disable <provider> <account>
anypick proxy config <provider> <account> [--port N]
anypick proxy restart <provider> <account>
anypick proxy logs <provider> <account> [--lines N] [--follow]
```

`enable`는 프록시를 구성하고 시작합니다. `config`는 포트를 변경하고 프록시를 다시 시작합니다. `restart`는 동일한 계정을 중지하고 시작합니다. `status`, `start`, `stop` 및 `logs`는 각각 정확한 `<provider> <account>` 쌍을 취합니다. "모든 프록시" 형식은 없습니다.

## Gemini 인증 소스

Gemini는 두 번의 로그인을 허용합니다. 계정이 저장하는 항목은 프록시별로 결정되는 것이 아니라 계정이 저장될 때 결정됩니다.

```bash
anypick add account gemini --current --source gemini-cli --name work
anypick add account gemini --current --source antigravity --name work
```

`--source`를 생략하면 AnyPick은 앱이 남긴 파일에서 이를 추론합니다(gemini-cli 먼저). 프록시는 저장된 스냅샷에서 제공되므로 고정된 소스를 전환한다는 것은 새 계정을 저장하는 것을 의미하며 카탈로그 별칭은 하나의 소스 내에 유지됩니다. Antigravity 롤아웃 ID는 실수로 Gemini CLI를 통해 전송되지 않습니다.

## OpenCode 인증 모드

Go 엔진은 실제로 로그인된 자격 증명에서 계정당 **하나** OpenCode 카탈로그를 확인합니다. Go 구독 행은 `https://opencode.ai/zen/go/v1`를 대상으로 하고 다른 모든 Zen/Go 주요 대상은 `https://opencode.ai/zen/v1`를 대상으로 합니다. TypeScript `--auth-mode auto|public|api` 플래그, 모델별 카탈로그 라우팅 및 `OPENCODE_PROXY_UPSTREAM` 재정의는 이식되지 않습니다. 제공하려는 자격 증명에서 계정을 저장하세요.

키는 다음 순서로 조회되며 첫 번째 히트가 승리합니다.

1. 라이브 CLI 자격 증명 저장소(`opencode.db`, `OPENCODE_DATA_DIR` 아래)
2.  `opencode.db`가 계정의 `auth.json` **옆에** 저장되었습니다.
저장된 스냅샷에 3. `auth.json`가 있습니다.

베타 CLI가 더 이상 로그인 시 `auth.json`를 다시 작성하지 않기 때문에 라이브 저장소가 먼저 확인됩니다. 그렇지 않으면 계정을 전환하기 전에 저장된 스냅샷이 이전 계정의 키를 계속 제공하게 됩니다.

저장된 로그인에 Zen/Go 키가 없는 계정(예: ChatGPT 또는 Anthropic 로그인과 같은 OAuth 전용 `auth.json`)은 이 프록시를 구동할 수 없습니다. 해당 로그인은 대신 `anypick use`에 의해 기본 클라이언트에 적용됩니다. `NO_LIVE_AUTH`로 인해 프록시가 실패합니다.

- 저장되지 않음 `auth.json` 전혀: *사용 가능한 OpenCode 인증이 없습니다.* `opencode auth login` / `anypick add opencode --name <name>` 제안 포함;
- `auth.json` 존재하지만 읽을 수 없음: *읽을 수 없는 OpenCode 인증: &lt;path&gt;.*;
- `auth.json` 읽을 수 있지만 OAuth 행만 보유합니다. *OpenCode 프록시에는 auth.json 또는 CLI 자격 증명 저장소에 Zen/Go API 키가 필요합니다...*.

## 다중 계정 풀

기본값은 계정당 하나의 프록시 프로세스입니다. 풀은 단일 포트 뒤에 한 공급자의 여러 계정을 배치하므로 클라이언트는 하나의 엔드포인트를 확인하고 AnyPick은 회전을 처리합니다.

```bash
anypick proxy pool enable gemini -p 4150
anypick proxy pool member gemini work on
anypick proxy pool member gemini alt off      # keep it configured but paused
anypick proxy pool status gemini

anypick use claude --with pool:gemini

anypick proxy pool disable gemini             # back to one process per account
```

터미널 UI의 프록시 보드에서 `p`는 풀을 전환하고 <kbd>space</kbd>는 커서 아래에 있는 구성원을 일시 중지하거나 다시 활성화합니다. 다중 계정 풀 행에서 <kbd>f</kbd>는 안전 할당량 기반 장애 조치 가드를 전환합니다.

<Aside type="note" title="의도적으로 선택">
풀은 공유 상태입니다. 포트 1개, 자격 증명 여러 개, 교체는 요청별로 표시되지 않습니다. 장애 조치가 포함된 하나의 엔드포인트를 특별히 원하지 않는 한 계정별 프록시를 선호합니다.
</Aside>

### 장애 조치, 순환 및 할당량 보호

`--strategy failover`(기본값)는 마지막으로 응답한 계정에서 계속 서비스를 제공하고 해당 계정이 거부된 경우에만 계속 진행합니다. `--strategy
round-robin`는 대신 링의 다음 멤버에서 각 요청을 시작하므로 연속 요청이 계정 전체에 분산됩니다.

```bash
anypick proxy pool enable kiro --strategy round-robin
```

두 전략 모두 *적격* 회원에게만 적용됩니다. 할당량 가드가 쿨다운을 설정한 계정은 건너뛰고 순환도 건너뜁니다. 차이점은 시도가 실패했는지 여부가 아니라 시도가 시작되는 위치입니다. 할당량 클래스 오류로 응답하는 멤버는 여전히 요청을 다음 요청으로 전달합니다.

**모든** 구성원이 냉각되고 있을 때 풀은 계속 서비스를 제공합니다. 즉, 가장 빨리 복구될 계정을 시도하고 로컬에서 거부하는 대신 공급업체의 응답을 호출자에게 다시 전달합니다. 한 번의 시도만 가능하므로 완전히 조절된 공급자는 링 워크로 인해 방해를 받지 않습니다. 따라서 소진된 구독은 공급업체가 말한 내용(`429`, `402` 또는 재설정 시간)을 정확하게 표시하며, 이에 따라 클라이언트가 조치를 취할 수 있습니다.

```jsonc
// ~/.anypick/config.json — set false to restore the local refusal
{
  "ui": {
    "quotaGuard": {
      "enabled": true,
      "cooldownMinutes": 60,
      "serveWhenAllCooling": true
    }
  }
}
```

가드 자체는 풀별로 전환됩니다. 터미널 UI의 풀 행에 있는 <kbd>f</kbd> 또는 위 구성의 `enabled`입니다.

## 프록시 허브(선택)

풀은 하나의 공급자를 유지합니다. 통합 **프록시 허브**는 하나의 로컬 엔드포인트 뒤에 저장된 여러 계정을 노출하고 모델별로 라우팅할 수 있는 별도의 옵트인 표면입니다. 기존 바인딩을 다시 작성하지 않고 활성화하고 소스를 추가한 다음 바인딩합니다.

```bash
anypick proxy hub enable default -p 4140 --start
anypick proxy hub source default grok work
anypick proxy hub status default
anypick use claude --with hub:default
```

### 회전: 허브에 대한 하나의 전역 모드

허브의 모든 계정에는 자체 켜기/끄기 스위치가 있으며, 허브에는 사용자가 켠 계정 중에서 요청을 선택하는 방법에 대한 하나의 전역 모드가 있습니다. 기본적으로(`failover`) 각 모델은 해당 모델을 소유한 계정으로 이동합니다. 또는 모델에 대한 소유권이 주장되지 않은 경우 첫 번째 소스로 이동합니다. **계정 간 순환**은 각 모델을 *제공할 수 있는 모든 활성화된 계정*에 분산하므로 모든 요청을 하나가 처리하는 대신 저장된 Gemini 로그인 3개가 작업을 공유합니다.

```bash
anypick proxy hub enable default --strategy round-robin
```

"제공 가능"은 공급자 카탈로그에서 나오므로 동일한 모델 ID(예: 호환성 프록시 및 공급업체)를 광고하는 두 공급자가 모두 교대로 사용됩니다. 요청한 모델을 제공할 수 없는 계정은 선택되지 않습니다. 카탈로그가 모델에 대해 아무것도 모르는 경우 회전은 모델이 확인하는 공급자 내부에 유지되며 기록된 모델 소유자는 여전히 어떤 공급자가 응답하는지 결정합니다. 회전은 *어떤 계정*이 응답하는지만 변경합니다.

계정별 전환은 전체 멤버십 규칙입니다. 꺼진 계정은 결코 후보가 아니며 공급자의 모든 계정을 끄면 해당 공급자가 허브에서 제거됩니다. 허브가 요청별로 소스를 확인한 다음 이를 확산시키기 때문에 공급자당 하나의 스위치가 아닌 전역 모드입니다.

허브는 또한 **자체 할당량 보호**(동일한 `ui.quotaGuard` 설정)를 유지합니다. 키나 계정이 할당량을 벗어났기 때문에 공급업체가 요청을 거부하면 해당 계정은 냉각되고 요청은 동일한 모델을 제공할 수 있는 다음 활성화된 계정으로 이동합니다. 자격 증명(실제 500, 분당 속도 제한)을 비난하지 않는 공급업체 거부는 그대로 전달됩니다. 허브는 다른 계정의 할당량을 여기에 사용하지 않습니다. 모든 후보가 냉각 중일 때 `serveWhenAllCooling`가 거짓이 아닌 한 가장 빨리 회복하고 평결을 통과시키는 후보에게 서비스를 제공합니다. 풀 프록시는 자체 경비를 유지합니다. 이는 허브에만 적용됩니다.

프록시 보드는 구성 시 허브를 자체 행으로 나열합니다. <kbd>enter</kbd> 또는 <kbd>m</kbd>는 허브 편집기를 엽니다. 공급자 간에 하나의 공유 엔드포인트가 특별히 필요하지 않은 한 일반적인 계정별 프록시를 선호합니다.

## 프로세스 소유권

기본 macOS 아키텍처에서 `AnyPick.app`는 번들 Go 서비스를 소유하고 Go 서비스는 로컬 프록시 프로세스를 소유합니다. 기본 창을 닫으면 앱이 계속 실행됩니다. 명시적 앱 종료는 도우미와 해당 서비스를 정상적으로 중지합니다. 메뉴 표시줄 항목은 독립형 감독자가 아닌 동일한 앱의 보기입니다.

Go 엔진은 동일한 감독자를 직접 소유합니다(`cmdTray` / `runSuperviseChild` in `src/go/cmd/anypick/lifecycle.go`):

```bash
anypick tray          # app surface (same core as `anypick app`)
anypick tray start
anypick tray status
anypick tray stop     # stop that supervisor and the proxies it owns
```

이 저장소에서 `make run ARGS="…"`를 사용하여 해당 양식을 실행하세요. <kbd>q</kbd>를 사용하여 TUI를 닫으면 백그라운드 감독자 상태가 변경되지 않습니다. <kbd>Shift+D</kbd> 및 <kbd>t</kbd> 작업은 별도로 실행되는 기본 앱을 관리하지 않습니다.

고아는 축적되지 않고 정리됩니다. 시작 시 AnyPick은 소유 프로세스가 종료된 임대를 해제하고 해당 프록시를 중지합니다.

Linux 및 Windows Tauri 설치 프로그램은 macOS 앱과 동일한 릴리스 워크플로에서 게시됩니다. 현재 자산은 [출시 페이지](https://github.com/outof0/anypick/releases/latest)를 참조하세요. 별도의 트레이 전용 설치 프로그램은 없습니다.
